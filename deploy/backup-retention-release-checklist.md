# 备份治理上线清单

## 变更边界

- 开发基线：已发布 `v1.18.29`，提交 `1151c0ab810bfdba499b7a537bb71974acd16762`。
- 本轮仅包含：在线成套备份保留与重启周期复用、旧备份删除保护、宿主机发布/清理公共锁、测试和说明。
- 不修改业务表结构、业务计算、页面、采集器、鉴权、NewAPI 或其他容器；不提交备份、生产配置或本机验收数据。
- 开发目录独立于其他未完成业务改动，不能用其他开发分支的整体合并代替本轮提交。

## 分开交付，默认不启用新淘汰策略

1. 先提交、打不可变 tag、完成 CI 和镜像检查。2026-10-15 只读核对时 `v1.18.30` 尚未占用；打 tag 前需再确认，不覆盖已有 tag。
2. 正式发布前重新读取当前镜像 digest、revision、配置和全部容器挂载；如果线上基线已变，停止并重新核对，不按本文假定版本强行发布。
3. Monitor 新镜像保持 `MONITOR_STORE_BACKUP_RETENTION_DAYS=0`，保留现有按套数策略，关闭重启复用。新代码仍会加强淘汰前校验，因此不是“所有内部行为零变化”。
4. 宿主机脚本是独立交付物，不在 Monitor 镜像中。只安装经审核的 `monitor_release_guard.py` 和 `release_backup_retention.py`，与版本专用发布脚本配套；此步骤必须另获生产变更授权。
5. 发布、回滚、备份挂载调整必须统一使用公共锁；未覆盖的旧入口不得与新入口并行使用。只要仍有入口绕过锁，就不得开启自动删除。
6. 初次使用 `--cleanup plan`，只审核计划。不安装按目录年龄递归删除的 cron，不执行 `--cleanup apply`。
7. 后续另行授权开启日保留策略或执行冷备份清理；不和首次镜像切换一起开启。开启后检查第一次备份/淘汰周期，不只看容器启动成功。

## 切换前硬性检查

- 明确旧镜像 digest 和原配置可恢复，禁止使用 `latest` 作为发布或回滚目标。
- 记录 Monitor、Usage 入口和其余容器的上线前状态，以及四模块已登录只读基线；不能只看未登录页面返回 200。
- 按现有已审核部署流程生成本次一致性冷备份，核验 hash、SQLite 完整性、权限与成套恢复能力。不可把运行中的 `.db` 单独复制作为一致性备份。
- 磁盘、内存和 inode 有足够余量；生成新备份前不得为了腾空间先删除最近恢复点。
- 以 Docker 实际挂载为准，任何容器引用的目录均保护，不能根据目录名含 `backup` 就判断可删除。
- 不运行整套 `docker compose down`，不触动其他服务，不在公网开放测试端口。

## 切换与上线后验收

- 只切换 Monitor，维持原挂载、环境配置及其他服务状态。
- 按版本专用发布脚本的启动宽限和检查期限验收：容器 running/healthy、无 OOM/持续重启；检查反向代理及 `/live`、`/ready` 实际探针，不能仅凭 HTTP 200 忽略响应体中的降级原因。
- 从外部入口确认 Monitor 与 Usage 可用；只读核对用户用量、渠道管理、稳定性报表、经营核算及后台同步状态。与基线对比，不把已有数据缺口误报为新增故障。
- 验收失败不生成成功凭据，不清理备份。禁止为了通过验收跳过错误或手写 READY。
- 验收通过后，`accept` 必须生成本轮新鲜成功记录；清理计划需再次核对运行镜像、恢复点、候选文件及挂载。
- 关注新增备份校验的后台 I/O 和耗时；它不在 HTTP 读请求内执行，但不能声称完全没有磁盘开销。

## 停止与回滚

- **只出现清理警告：**停止执行清理（`--cleanup off`），保留文件和审计，不停止 Monitor，不触发服务回滚。
- **日保留/重启复用异常：**恢复 `MONITOR_STORE_BACKUP_RETENTION_DAYS=0`。这只关闭新策略，旧的按套数保留仍然存在；不是“关闭全部备份删除”。按已批准方式仅重建 Monitor 使配置生效。
- **新版服务异常：**使用同一公共锁下已审核的 `rollback-image`，恢复原镜像和配置，保留当前数据卷；核对服务入口和其余服务状态。没有本轮数据库迁移，不以恢复旧业务库作为普通镜像回滚步骤。
- **备份恢复只用于真实数据损坏：**必须单独授权、保留故障现场、在独立目录验证完整恢复集，再制定恢复步骤，不能自动覆盖在线库。
- 已淘汰的旧备份不能通过关开关恢复。此功能保证保留恢复点，而不是保证每个过期快照可撤销删除。
- 公共锁冲突返回 75；不要删除锁文件“解锁”。先确认持锁进程是否仍在工作。清理失败返回维护警告，不作为回滚触发条件。

## 本机验收与剩余门禁

本机已覆盖：32 项 Linux 断网脚本演练、Go 备份/恢复与就绪回归、竞态检测、Linux 合成双库恢复、全部 Go 包静态检查、前端原有渲染回归及 CI 分片覆盖检查。

这些不等同于已完成 GitHub CI、候选发布镜像验收或生产上线验收。脚本演练使用模拟容器状态；生产安装时仍需核对实际发布脚本协议和真实挂载。没有安装生产公共锁入口之前，不允许自动清理。
