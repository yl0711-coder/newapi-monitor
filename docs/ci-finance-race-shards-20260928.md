# 经营核算 CI 分片调整

## 目的与边界

v1.18.8 的 CI 36429352462 在 `^TestF` 竞态分片累计运行 20 分钟后超时。超时当时的子测试只执行了 3 秒，之前仍持续推进；不能将这个堆栈误判成单个测试死锁 20 分钟，也不能据此认定所有未跑完测试都正确。

本轮仅调整 CI 调度、覆盖校验和耗时报告，不改 Monitor 业务代码、SQLite 结构或测试断言，不连接或修改生产服务。没有延长 Go 测试的 20 分钟超时，也没有删除测试或移除 `-race`。

## 分片规则

原来的 `TestF` 拆为四组：

| 分片 | 包含 | 排除（由其他组完整执行） | 本机测试入口数 |
|---|---|---|---:|
| f-other | TestF | TestFinanceGift | 207 |
| f-gift-other | TestFinanceGift | TestFinanceGiftScope / TestFinanceGiftHandoff | 85 |
| f-gift-handoff | TestFinanceGiftHandoff | 无 | 30 |
| f-gift-scope | TestFinanceGiftScope | 无 | 40 |

其余五组保持不变，整体由六组变为九组。这里的入口数来自 Go 1.26.6 的实际 `go test -list .` 清单，不包括嵌套子测试；不同平台以本平台 Go 生成的清单为准。

覆盖校验直接读取工作流矩阵，考虑包含与排除规则，对全部 2031 个本机测试入口验证恰好分配一次，同时拒绝空分片、重复名字、无效选定分片及子测试路径规则。CI 每个分片再次校验自己的构建平台清单。

注意：Go 的 `-list` 不应用 `-skip`，不能用 `go test -list pattern -skip pattern` 的行数冒充真实选中数量。因此由统一校验器计算分片数量，实际运行使用同一矩阵的 `-run` / `-skip`。

## 可观察性与失败处理

- 每组 `go test -race -count=1 -json -timeout 20m`，避免把测试缓存命中当成本轮执行。
- `pipefail` 保留测试失败退出码，不因 `tee` 保存报告成功而错误放行。
- 作业总时限 30 分钟，覆盖构建和测试；Go 测试自身仍为 20 分钟。
- CI Summary 记录包耗时、通过/失败/跳过入口数、最慢 15 个顶层测试、失败和未完成测试，不把父子耗时重复相加，不转载测试原始数据。
- JSON 事件作为 GitHub Actions 工件保存 7 天，便于下一轮按真实耗时调整。不创建 AWS/S3 资源。
- 原有安全检查、镜像扫描及发布依赖关系保持不变，任何分片失败仍阻止镜像发布。

## 效率预期与后续边界

本轮降低单分片等待时间，不保证总 runner 分钟数下降：增加分片也会增加构建启动开销。整体 CI 还受其他分片、镜像构建扫描及并发配额约束，不能承诺几分钟完成。

后续如需减少总计算量，应单独治理测试 fixture：普通单元测试仅初始化所需表，完整建库/迁移/备份保留独立集成覆盖，每个用例仍使用独立可写数据库。本轮不混入此重构。

## 本地验收

在 HEAD v1.18.8 的独立副本中只加入本轮 CI 修改，排除工作区其他未提交优化。使用 Go 1.26.6 构建真实竞态测试二进制，用同样的包含/排除表达式执行四个财务分片；不访问生产数据库。

- YAML 解析和九组矩阵验证通过。
- 分片与耗时报告 8 项专项测试通过。
- 全部前端/开发脚本测试 129 项：127 通过，2 项原有外部工件 opt-in 测试跳过。
- 完整测试清单覆盖校验通过：2031 项，零遗漏、零重复。
- 四组真实竞态执行通过：f-other 137.578 秒、f-gift-other 295.845 秒、f-gift-handoff 141.487 秒、f-gift-scope 143.168 秒。这是本机并发执行条件下的结果，不是 GitHub runner 性能承诺。
- 将四组 JSON 实际完成入口逐一对照 Go 清单：362 项完全一致、无遗漏/重复。其中 343 通过，19 项原有 opt-in 测试因缺少显式外部工件/环境而跳过，不声称这些外部集成测试已执行；未新增跳过条件。
- 实际运行日志可由新摘要脚本正确解析。失败管道、超时未完成列表、忽略敏感测试输出、非法分片及覆盖缺口有专项回归。

实际 GitHub runner 的最终耗时需新一轮 CI 验证；本地执行结果不能替代 GitHub CI 成功状态。
