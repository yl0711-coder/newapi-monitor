# 历史赠送补齐：小批次控制内核验收

## 本轮目标与范围

在已通过的单用户小时修复原语上增加批次执行控制。只开发、测试控制内核；没有接入 HTTP、页面按钮、启动循环或生产任务，没有再次读取生产。真实验收复用之前已取得的 11 条私有原始样本，并且只操作测试临时副本。

## 行为约束

- 显式计划，每批 1–10 个用户小时；不自动扫描或扩展为全量任务。整批先校验，拒绝重复目标、混用来源 epoch、当前未闭合小时和无效用户。
- 一个 runner 内串行执行，同一 runner 的并发请求直接拒绝；每个尝试结束后至少冷却 10 秒，跨批次沿用冷却状态。
- 单次来源查询继续使用已有 8 秒超时；这不替代将来真实来源读取前的索引/只读检查。当前来源连接没有绑定生产。
- 任一核验失败立即停止，失败目标和后续目标保留待处理；没有无限重试、自动跳过或自动提高并发。
- context 取消用于暂停：等待中可立即退出，来源查询中取消则不发布；若取消发生在提交后，先记录已提交结果，再停止后续小时。
- 恢复时重放同一显式计划，已核验事实作为持久检查点。已经完成的小时不请求来源、不写入、不重复分配赠送；不修改主同步游标。
- 逐小时结果包含来源 epoch、用户、小时、状态、检查/修改条数、内容 hash 和完成时间；失败审计只保存固定错误代码，不保存原始数据库错误或凭证。
- 必须提供审计回调。审计失败立即停，已提交小时不反向回滚，返回 `audit_failed` 提醒核验最后提交结果。真实副本验收使用私有 JSONL 并逐条 fsync；运行期持久审计入口尚未接入。

## 测试结果

本机 `go test -race ./monitor -run 'TestFinanceGiftScope|TestFinancePriorGiftChangeInvalidatesLaterReport' -count=1 -v -timeout 3m`（设置已有私有样本路径）通过，19.873 秒；`go vet ./monitor`、`git diff --check` 通过。

覆盖：

1. 两用户串行修复、10 秒冷却、跨批次冷却、重复计划零来源查询。
2. 首小时完成后暂停、恢复时跳过已完成小时、处理剩余小时。
3. 缺来源和审计写入失败均停止后续处理；提交后审计失败再执行不会重复修改。
4. 超过 10 个目标、重复目标、无效用户、混用 epoch、未闭合小时、缺审计接收器、开始前取消均不执行。
5. 同一 runner 并发拒绝；来源查询中取消保持旧事实。
6. 真实样本经过批次入口仍逐条匹配 11/11，quota 7944 和退款 0 不变，未知分组 11→0，赠送消耗 $0.015888；新建 runner 模拟进程恢复，来源为 nil 仍可确认已完成目标，零更新。
7. JSONL 落盘结果逐条解码，与批次返回的“修复 / 已完成”结果一致；全量用户金额事实和主同步游标保持不变。

测试中注入虚拟时钟验证冷却语义，不实际等待每个 10 秒；生产默认使用可取消的真实定时器。没有因此得出生产批量回填性能结论。旧库读取的慢 SQL 日志来自临时测试副本的全量守恒比较，不是生产查询。

## 尚未完成的接入与下一步

- 当前未接入面向用户的“开始/暂停”入口，也未安装后台任务；因此页面数据不会因这一步发生变化。
- 下一步只做本地手动验收入口：预览固定计划、记录任务文件、单执行者运行、持久化审计与关闭/重启恢复校验。必须复用现有只读来源安全检查，不开放任意 SQL。
- 当前互斥仅针对单个 runner，不宣称已经支持多进程/多实例分布式互斥。正式执行入口必须保证唯一 worker；不能同时创建多个 runner 绕过限速。
- 新建进程的冷却状态尚不跨进程持久化；正式入口接入前应由任务状态恢复或启动冷却保护，当前不得当作可反复启动的生产限速器。
- 没有启动 915 个用户小时的全量补齐，没有修改生产或本机 8112 预览数据卷，没有上线。本轮不是完整上线验收。
