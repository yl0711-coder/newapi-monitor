# Usage 账单后台任务：独立内核阶段

## 本轮范围

仅新增 `internal/usagebill/exportjobs` 及测试。没有注册 HTTP 路由、启动 Monitor 新循环、连接数据库、调整客户页面、改变 5 万条现有上限或金额/价格口径，也没有提交、部署、线上操作。

这不是后台账单功能已全部上线可用；先把任务生命周期单独验证，再接来源读取与客户接口。

## 已实现规则

- 有界任务表与队列，一个 Manager 单个生成 worker；同组保留一个任务，重复点击相同筛选/快照键复用任务 ID，不重复生成。
- 任务键由未来接口根据服务端规范化筛选、来源快照、格式与核算规则版本生成 SHA-256；身份必须从已验证会话派生，不接受客户自报组 ID。
- Owner 包含组织 ID、权限版本、成员指纹。创建、生成前后、状态查询和下载前均走授权回调；未知任务与错误归属不泄露数据。短暂授权读取失败拒绝访问，但不销毁已经完成的账单。
- 生成任务独立于创建请求连接，关闭浏览器不会直接中断工作。生成受总时间约束，排队剩余有效期也参与截止；取消和关闭要求来源读取遵守 context。
- 进度不允许倒退或超出预计条数；返回实际条数必须与预计一致。超限、超时、内部异常或行数不符均失败，不发布部分文件；即使生成器忽略写入错误也不能发布。
- 文件先在私有目录写入，再复核权限并原子改名为完成文件；记录字节数和 SHA-256，不向客户状态暴露文件路径或原始异常文本。
- 每个完成任务最多一个打开的文件句柄。下载持有文件引用期间不删除文件；取消/过期后拒绝新下载，最后一次 Close 清理文件。
- 正常关闭取消生成、清理自己的目录，不删除调用方目录、其他任务管理器目录或无关备份；重复关闭安全。
- 容量参数有硬边界：最多 8 个保留任务，单文件最多 128MiB，全部任务的配置字节上限合计不超过 256MiB；每次生成前还要求可用空间覆盖单文件预算并保留 256MiB。
- `MaxRows` 是必须由调用方选择的测试/接入上限，内核最多允许 100 万；**这不是生产已经允许 100 万行，更不是容量验收结论**。正式接入前按完整格式和实际分页测试决定。

## 本机验收

- 并发重复提交 30 次只生成一次；请求断开不影响已接受任务。
- 状态、下载的跨组、权限版本、成员范围隔离，以及生成末端权限变化阻断。
- 写入中途失败、异常、条数不符、进度错误、字节超限、忽略写入错误、生成超时，均无可下载部分文件；失败后可重试。
- 单 worker 排队、取消、关闭、过期、已有下载引用、短暂授权故障、重试冷却和私有目录保护。
- 修复了测试发现的重复关闭报错、取消后活跃文件不能复用、排队等待时间不得重新计时等边界。
- 新包竞态测试连续 5 轮通过（阶段覆盖率 84.8%，没有删除防御分支追求覆盖率）；金额包和现有 Usage 专项回归通过。
- 断网、只读根文件系统、1 CPU / 256MiB Docker 全部默认任务测试通过；另在独立 64MiB 临时磁盘容器中验证低空间拒绝，生成器没有被调用。两容器自动删除。
- 10 万条两列合成 CSV，逐行核对 ID 顺序、行数和整数金额合计通过。**只是任务层读写验收，不是完整 14 列账单、真实 RDS、真实全月模型或官方原价覆盖的性能证明。**

## 接入前必须补齐

1. 将已实现的启动回收接入 Monitor 生命周期，并验证滚动启动时的后续回收触发。当前内核创建 Manager 时自动扫描；尚未接入生产启动或周期任务。新 Manager 不恢复旧任务 ID，不会把旧文件自动交给新请求。
2. Monitor 实际生成适配器：冻结筛选/成员/来源上界，有界分页，复用已验收的 14 列与金额算法，独立核对条数/金额；不长时间持有来源事务。完整性不能只由生成器随意声明预计条数。
3. 与现有导出统一的跨进程生成锁、磁盘水位、成功限流和有界下载时限。内核不负责整个服务器的多进程资源分配，不直接实例化多个 Manager 当成扩容方案。
4. 服务端会话与来源版本校验、POST 防跨站检查、任务创建/查询/取消/下载接口，以及页面轮询、进度和错误反馈。
5. 全账期大数据量、来源变化、重启/回滚、客户权限变化、原价缺失等端到端验收。既有入口暂不切换。

不新增业务数据库表；采用短期任务的失效重建语义，而不是未经验证的跨发布续跑。最终如何展示和保存任务状态，随下一轮接口一起核验。

## 2026-10-16 追加：异常退出回收验收

### 实现边界

- 仅对专用私有暂存目录中带有正确版本标识的任务会话执行回收；必须取得该会话的独占文件锁，不能只根据目录名、PID 或文件时间认定进程退出。
- 生命周期锁覆盖生成、完成保留和下载期间。创建新会话与回收共享短时目录锁，避免初始化和清理互相冲突。
- 未知版本、初始化未完成、软链接、非普通标识文件、权限异常目录均保留。单次最多检查 128 个目录项，超限先报错，不做部分删除。
- 正常关闭同样核对标识和锁文件身份；重复关闭不会删除后来复用了相同路径的其他文件。
- 当前只完成内核启动回收及显式 Recover 调用，未添加 Monitor 周期回收循环。滚动启动时仍存活的旧进程会被跳过，其后续残留需要下次回收触发；接入时仍须验证。
- 不恢复旧任务，不修改业务数据库，不改变账单金额、列格式、当前入口和导出上限。

### 最终代码测试结果

- macOS：任务包竞态测试连续 5 轮通过；静态检查与 diff 格式检查通过。
- 真实子进程分别在生成中、已完成、持有下载引用时被测试程序强制终止：存活时不可回收，退出后已识别目录可回收，旧任务 ID 在新 Manager 中不可查询或下载。
- 未知目录、部分初始化、软链接、FIFO、目录扫描超限，以及重复 Close 后路径复用的保护测试通过。
- Linux ARM64：断网、只读根目录、1 CPU / 256MiB Docker 全套默认任务测试通过；独立 64MiB 临时磁盘容器的低空间拒绝测试通过。测试容器均自动删除，不连接线上。
- 上述证明的是任务生命周期和文件回收，不代替完整 14 列账单、真实来源分页、金额对账、HTTP 与页面端到端验收；整个后台账单功能仍未接入生产。
