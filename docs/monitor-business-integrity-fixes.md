# 业务报表完整性修复与验收边界

## 本次变更

- AICodeWith 历史完成状态按已闭合日期重新判定。跨日后继续使用原游标、逐 Key 暂存、原子发布和既有退避，不会因旧 `backfill_done` 永久跳过日结。
- 多 Key 批次跨午夜完成时，账户游标只能推进到该批次冻结的结束时间，不能跳过刚结束的一天。
- 仅提供自然日账单的上游，在没有可纳入的完整时间桶时也返回明确的区间不匹配原因；不按比例估算小时金额、不把未知消费当零。
- 数据同步诊断包含启用渠道但未配置账户的主域名、缺少倍率的启用渠道、未启用日志同步和认证失效；仅查询有上限的本地元数据。
- 滚动稳定性环比使用等长前一区间。已定稿覆盖与未定稿尾段分别说明，历史失败不能被正常尾部延迟掩盖。
- 容量曲线分别使用 RPM、TPM 和稳定率坐标轴；查询首尾不足整桶时，入口 RPM 和并发估计按实际时长计算。
- 分组治理放到两个导航的最后；首次成功快照前不显示零计数。开启测试不等于可以执行分组删除或改价。
- 源站探测默认无目标。移除目标后，当前资源与告警视图不再显示它，历史采样与告警仍保留。
- 同步页区分排队复核和真实缺失、历史累计计数和当前新增问题；暂停任务不显示预计完成时间。

## 验收与运行约束

1. 运行 Go 全套测试、针对改动的竞态测试、静态检查和无网络前端渲染测试。
2. 用隔离 Docker 预览检查真实备份；来源 worker、上游同步、AWS 采集与发信关闭。快照时间后的数据不会自动出现。
3. 分组治理如需真实验收，仅以 `monitor_ro` 经回环 SSH 隧道进行有界 SELECT，不启动另一套自动采集器。正式测试只允许当前来源租约持有者运行，并保留低优先级闸门。
4. 新镜像必须基于最新 main，并经过 CI 后才可作为正式发布候选。本机临时镜像不是发布产物。
5. 不修改中转站、路由、来源数据库或历史原始记录；不因页面问题触发全历史来源扫描。

## 仍需人工或运行验证的事项

- 无效的上游 Refresh Token 需要重新连接；重试无法恢复被撤销的认证。
- TokenForce 的组织、币种换算和明细契约需要用实际只读账号核对。配置位置参见 [接入说明](tokenforce-upstream.md)。
- 已暂停历史任务、未完成签收和上游迟到记账，必须在同步状态页继续跟踪，不能因代码测试通过标为完整。
- 小范围来源对账与本地日汇总核对，只证明已检验范围一致，不能宣称所有历史及全部上游达到财务审计标准。
