# 每日上游账户账单原值：第一步统一来源（本机）

## 确认的问题

月表上游账单原值来自账户小时/自然日账单，原日表statement却来自渠道配对经济账本；后者可能只是一部分渠道。即使上游账单已经存在，未完成渠道配对也会导致日原值为空，两者不是同一覆盖范围。原日表页面没有单列账户账单原值，只显示已配对客户成本，不宜把该列当作全部成本。

## 本轮范围

仅统一每日 `upstream_billed_cost` / `known_upstream_billed_cost` 的来源，并新增日表“上游账单原值”列。不改变修正成本、内部成本扣除、渠道配对贡献、赠送/收入公式、月表金额，不引入按请求比例分摊。

- 将原渠道账单读取与纯投影拆开，共用原来的单位/金额、窗口、重叠、临时账单、生命周期和完整性校验。渠道原接口仍使用同一规则，没有第二套日账单校验公式。
- 每个月组件批量读取账户生命周期、原账单和未覆盖活动范围，内存中按北京时间日边界投影，不逐日发起来源或SQLite查询。日账单和月组件一同缓存。
- 账户原值包含测试消耗；未配置/未接入来源及无法解析的历史渠道活动不被当成零成本。没有配置的上游不会触发补采。
- 完整日期才有exact值；部分证据保留known值；无数据不填0，真实0可保留。自然日账单不拆成小时来匹配局部日期。
- 新增 `bill_coverage`，不复用渠道配对覆盖。前端兼容旧响应：没有新覆盖字段时，不把旧版配对原值误标为账户账单。
- 月缓存schema升级7，完整报表键升级 `daily-account-bills-v1`，静态资源finance.js升级v46；旧缓存文件不删除，历史金额事实不修改。

## 独立确认的精度差异与后续边界

日已知金额相加为143,479,505,822微美元，月已知金额为143,479,505,827微美元，相差-5微美元（0.000005美元）。只读原始本地备份、逐域重算32个已知账单来源后，两端结果分别精确重现：源行一致，差异来自按日分别取整与按整段取整，并非少采了日志。本轮不向某一天强加差额、不改变月金额；**未宣称微美元级日/月已完全守恒**。下一步应明确统一精度规则，再验证对月表及历史缓存的影响。
