# 02\.2｜全链路监控技术与生产运行方案

**状态：** 可进入研发分析
**维护时间：** 2026\-08\-25
**版本：** v2\.0

---

## 1\. 方案定位

本文规定 Monitor 的总体架构、组件边界、数据责任、生产运行和实施顺序。类、函数、DDL、算法和页面代码由研发在详细设计中确定。

共享契约以 [01\.3｜共享数据、状态与 Monitor\-Eval 联调契约 v1](https://scn7buedwig4.feishu.cn/wiki/UfbbwAnsyiEDRQkpabzc3lbIn4d) 为准，产品需求以 [02\.1｜全链路监控需求与产品方案](https://scn7buedwig4.feishu.cn/wiki/NVOdwONWKigEzrkIyU2cMzKsn4S) 为准。

## 2\. 核心技术决策

1. 旁路、只读、异步，不进入用户请求链路，不写 NewAPI 生产数据库；

2. 复用现有 Go 服务、SQLite/WAL、备份恢复、邮件、hostagent、reject 和 Nginx collector；

3. 先统一事件与数据质量，再建设 Incident，最后接边缘和客户端证据；

4. 采集、规则、查询和通知通过持久化事实解耦；

5. 单活可作为首期形态，但必须有外部 dead\-man、备份恢复和明确 RTO/RPO；

6. 首期生产处置全部人工审批。

## 3\. 逻辑架构

|层|责任|关键约束|
|---|---|---|
|Source Adapter|增量读取或接收 NewAPI、Nginx、reject、host、AWS、Eval、客户端事件|独立游标、失败隔离|
|Normalize|统一时间、维度、fault class 和脱敏字段|只使用 observability\.v1|
|Reliability|去重、重放、水位、守恒和缺口检测|业务事件与 telemetry gap 分离|
|Correlation|请求级或时间窗关联|明确 evidence level|
|Incident Engine|连续窗口、影响面、严重度、状态和去重|不触发生产写操作|
|Query \& Notify|页面、检索、通知、ACK 和审计|权限分层、敏感值不进 URL|

模块可以先在现有服务内实现，不要求拆成微服务。

## 4\. 数据源技术方案

|数据源|接入方式|M0/M1|关键验收|
|---|---|---|---|
|NewAPI|生产只读增量查询|M0|游标、延迟、权限和对账|
|Nginx|节点采集器分钟聚合|M0|全节点、轮转、积压和脱敏|
|reject|现有批量 ingest|M0|batch 幂等和入口覆盖|
|hostagent|现有 agent|M0|版本统一和节点心跳|
|E2E/cert|现有 probe|M0|域名、区域和阈值|
|API\-evaluator|共享契约双向联调|M0|幂等、重放、DLQ 和版本|
|AWS 边缘|S3/CloudWatch 异步拉取|M1|专用只读身份、游标、成本|
|客户端事件|授权后批量接入|M1|防重放、采样同意和脱敏|

每个源必须登记 Owner、周期、最后成功、最后事件、水位、lag、丢弃、解析失败、凭证到期、版本和节点覆盖。

## 5\. 数据模型与存储

概念实体包括 Source Event、Normalized Observation、Incident、Incident Evidence、State Transition、Source Cursor、Notification Outbox 和 Eval Reference。

首期继续使用 SQLite/WAL。研发详细设计必须给出唯一键、索引、事务边界、数据保留和迁移回滚。满足任一条件时启动存储 ADR：

- 写锁或事务等待持续影响采集；

- 核心查询 P95 连续超 2 秒；

- 文件增长使备份恢复无法满足目标；

- 30 天预测达到单机磁盘 70%；

- 单机无法在目标时间追平补采缺口。

## 6\. 关联与证据

关联顺序为：同一 HMAC 请求/Attempt ID、同业务维度窄时间窗、多源统计相关、不可观测。HMAC 携带 key id 并支持双 key 轮换；传播一致性未通过验收前，不启用精确关联文案。

Monitor 对入口、relay 前拒绝、NewAPI 日志和采集水位做窗口级守恒。差异只用于发现数据盲区，不强行生成业务故障。

## 7\. Incident、指标与接口边界

Incident 稳定键不包含滚动窗口。状态使用 observed/recommended/approved/applied 四层模型。

性能指标严格区分 TTFB、TTFE、TTFC、TTFT；thinking、工具和控制事件不得计为 TTFT。分位数必须同时展示样本和时间窗。

系统接口只有三类：Collector 向 Monitor 采集、Monitor 向 API\-evaluator 创建受控任务、API\-evaluator 通过 outbox 发布结果。具体路径和 Schema 由 [01\.3｜共享数据、状态与 Monitor\-Eval 联调契约 v1](https://scn7buedwig4.feishu.cn/wiki/UfbbwAnsyiEDRQkpabzc3lbIn4d) 管理，技术方案不重复实现样例。

## 8\. 采集器可靠性

|控制|要求|
|---|---|
|队列|同时限制记录数和字节数，不超过节点可用盘的批准比例|
|磁盘|70% 提醒、80% 降低保留/速率、90% 停止落盘并告警|
|丢弃|仅硬上限后丢最旧低严重度数据，并上报数量|
|重试|指数退避\+jitter，限制最大间隔和发送速率|
|日志|按大小和时间轮转，限制总空间|
|游标|原子持久化，重启从已确认水位继续|
|时钟|NTP 偏差超过 2 秒产生数据质量事件|

AWS 异步源采用对象/页游标、时间重叠窗口、事件去重和 source watermark，不能只按本机当前时间拉取。

## 9\. 安全与权限

- 采集身份按环境×节点×采集器拆分，禁止共用永久 Token；

- 凭证带 key id、scope 和过期时间，支持双 key 轮换；

- AWS 使用专用只读角色，不使用个人登录凭证；

- 不直接挂载 Docker socket；需要容器元数据时使用受限代理；

- 不采集密钥、正文、thinking 或工具参数；

- `raw_error` 只保存脱敏摘要；

- 敏感证据单独加密、最小权限和访问审计；

- 精确查询使用 POST body，不把敏感标识放入 URL。

## 10\. SLO、备份与恢复

|指标|首期目标|说明|
|---|---|---|
|月可用性|≥99\.5%|外部探针测量，不等同业务 API SLO|
|RTO|≤30 分钟|恢复查询和告警能力|
|RPO|≤24 小时|与当前每日备份实现一致；可补采数据另行追平|
|数据新鲜度|95% 不超过 2 个采集周期|按数据源分别统计|

当前备份配置以小时为单位、默认 24 小时。本期先完成每日一致性备份、独立故障域、校验和、保留策略和季度恢复演练；若业务评审要求更短 RPO，再通过 ADR 扩展备份频率，不把 15 分钟归档作为 M0 默认任务。

恢复流程必须验证数据库完整性、schema、游标、Incident、outbox 和 Eval 去重键，并在恢复后补采、对账和记录实际 RTO/RPO。

## 11\. 容量与值班

上线前必须填写节点数、峰值 RPS、事件大小、保留天数、规则量、查询并发、补采峰值和通知峰值，并完成正常写入与补采压测。

|严重度|ACK|首个决策|升级|
|---|---|---|---|
|SEV0|2 分钟|5 分钟|运维、研发、业务负责人；10 分钟无 ACK 升级|
|SEV1|5 分钟|10 分钟|当班\+系统负责人；15 分钟无进展升级|
|SEV2|15 分钟|30 分钟|当班处理，必要时通知渠道负责人|
|SEV3|工作时间|1 个工作日|数据质量或缺陷队列|

通知至少两个独立通道；dead\-man 不依赖 Monitor 自己。仅 SEV0 可由双人使用限时、审计、自动过期的 break\-glass；仍由人工按 NewAPI 方案执行。

## 12\. 实施阶段

### M0

- 统一事件、数据质量、Incident、状态和通知；

- 收口 NewAPI/Nginx/reject/host/E2E；

- 完成 Monitor—API\-evaluator 联调；

- 完成备份恢复、磁盘保护、凭证和 SEV 演练；

- 保持只读和人工处置。

### M1

- AWS 边缘和客户端直接证据；

- 请求级关联；

- 双通道、容量和基线优化；

- 24 小时、7 天、30 天运营视图；

- 自适应规则、事故知识和查询优化；

- 达到迁移门槛时执行存储 ADR；

- 自动生产处置仍不在范围内。

## 13\. 研发详细设计与验收

研发编码前提交模块映射、数据模型、索引、游标补采、并发背压、Schema 复用、迁移回滚、容量和测试计划。

上线验收至少包括：全节点覆盖；数据源断开不误判健康；Incident 不因窗口重复；联调重复/乱序/重放通过；敏感数据和权限通过；备份恢复达到 RTO/RPO；采集队列和磁盘演练通过；Monitor 全停不影响 NewAPI；自动写 NewAPI 数量为 0；shadow 至少 7 天。
