# 01\.3｜共享数据、状态与 Monitor\-Eval 联调契约 v1

**状态：** 研发基线
**维护时间：** 2026\-08\-25
**版本：** v2\.0
**契约版本：** observability\.v1

---

## 1\. 目的与权威性

本文是 Monitor、API\-evaluator 和 NewAPI 文本渠道治理的唯一共享契约。其他文档出现不同字段、枚举、指标或联调方向时，以本文为准。

本文冻结系统责任、标识、故障分类、证据等级、治理状态、指标口径、联调语义、冲突仲裁、恢复门禁和敏感数据边界。研发应据此产出机器可校验的 Schema 与详细接口设计；本文不规定实现代码、表结构或消息中间件。

## 2\. 系统责任与事实来源

|事实|权威来源|
|---|---|
|生产请求、真实流量和基础设施观察|Monitor 只读事实库|
|主动测试执行、协议终态和测试证据|API\-evaluator|
|渠道启停、优先级、权重和分组实际值|NewAPI rc4 配置快照|
|Incident 聚合、`observed_state` 和 Monitor 建议|Monitor|
|测试 `recommended_state`|API\-evaluator|
|`approved_state`|人工审批记录|
|实际生产变更|NewAPI 操作审计|
|客户端重试、压缩和最终交付|经授权的客户端直接遥测|

任何系统都不得把局部事实声明为最终真实状态。Monitor 和 API\-evaluator 不持有 NewAPI 生产写权限。

## 3\. 标识与时间

所有机器时间使用 RFC 3339 UTC；页面可显示北京时间，但须保留时区和原始时间。

|字段|规则|
|---|---|
|`incident_id`|Monitor 生成，全局唯一|
|`event_id`|事件生产方生成，消费幂等键|
|`source_event_id`|来源内唯一，用于重放去重|
|`eval_run_id`|API\-evaluator 的一次运行标识|
|`attempt_id`|每次实际网络请求标识，API\-evaluator 必填|
|`target_id`|渠道、模型、协议、分组和探针区域的唯一组合|
|`logical_request_key`|仅由受信客户端或网关明确提供；不得推测|
|`gateway_request_id_hash`|原始网关请求 ID 的版本化 HMAC|
|`config_change_ref`|审批或配置变更记录；无变更时为空|
|`schema_version`|当前固定 `observability.v1`|

原始请求 ID 只可在受限排障过程中短暂使用。长期关联只保存带 `key_id` 的版本化 HMAC；密钥轮换须覆盖最长查询窗口，旧密钥到期销毁，历史数据不反向解密。

## 4\. 统一故障分类

`fault_class` 只使用下列枚举。异常存在但不能分类时用 `unknown`；应有证据但缺失时用 `telemetry_gap`，两者不可互换。

|枚举|定义|
|---|---|
|`transport_connect`|DNS、TCP、TLS 或连接建立失败|
|`transport_timeout`|连接、读写或总超时|
|`upstream_first_byte_slow`|上游响应头相对基线持续变慢|
|`stream_first_event_slow`|首个合法协议事件相对基线持续变慢|
|`text_first_content_slow`|首个用户可见文本相对基线持续变慢|
|`stream_interrupted_before_first_event`|首个合法事件前终止|
|`stream_interrupted_midstream`|已有事件但未到合法终态|
|`client_gone`|下游在服务端观察点提前关闭，不直接归责渠道|
|`protocol_invalid`|JSON、SSE、字段或事件顺序不合法|
|`responses_incomplete`|Responses 缺少合法成功终态或明确返回不完整|
|`thinking_signature_invalid`|thinking signature 缺失、损坏或错配|
|`tool_call_invalid`|工具名、参数、call id 或结果续接不合法|
|`route_no_channel`|无可用渠道|
|`model_not_found`|文本模型不存在或映射错误|
|`auth_quota_account`|上游凭据、余额、账户或权限确定性错误|
|`rate_limit_capacity`|429、RPM、TPM、并发或容量不足|
|`upstream_5xx`|上游 5xx|
|`empty_or_truncated_output`|文本空输出或截断|
|`billing_anomaly`|usage、token、扣费或重复计费异常|
|`semantic_quality`|回答质量不达标；不用于自动隔离|
|`client_retry_loop`|客户端直接证实的重试循环|
|`client_compaction`|客户端直接证实的上下文压缩|
|`telemetry_gap`|已知应有证据但观察点缺失|
|`unknown`|有异常事实但仍无法分类|

一个 Incident 有一个 `primary_fault_class` 和零到多个 `companion_fault_classes`。不得用自由文本新造同义故障类型。

## 5\. 证据等级

|枚举|含义|治理用途|
|---|---|---|
|`exact`|同一 ID 或 Attempt 的直接事实，或确定性定向复现|可支持隔离建议，仍须结合影响与审批|
|`correlated`|多源在相同维度和窗口高度相关|最多支持 `DEGRADED`，隔离前需补强证据|
|`inferred`|启发式或弱相关推断|只用于排查方向|
|`unavailable`|没有必要观察点|不支持健康或处置结论|

API\-evaluator 的 `high/medium/low` 是测试置信度，不得代替 evidence level。客户端最终完成、重试或压缩只有客户端直接事件才能标记 `exact`。

## 6\. 状态、严重度与优先级

治理状态唯一枚举为：`HEALTHY`、`SUSPECT`、`DEGRADED`、`QUARANTINED`、`RECOVERY_PROBATION`。

|状态层|含义|权威方|
|---|---|---|
|`observed_state`|基于生产真实流量计算|Monitor|
|`recommended_state`|基于观测或测试给出的建议|建议方|
|`approved_state`|人工批准的治理决定|审批记录|
|`applied_newapi_state`|NewAPI 实际启停、分组、优先级和权重|NewAPI|

NewAPI 的 enabled/disabled 不能替代治理状态。Monitor 每 1 至 5 分钟只读同步实际配置；审批与实际配置不一致时生成 `configuration_drift` 数据质量事件，不自动覆盖任一方。

事故严重度只用 `SEV0/SEV1/SEV2/SEV3`；研发优先级只用 `M0/M1`，运行时接口不传研发优先级。定义以 [01\.2｜文本模型专项范围、基线与研发交接](https://scn7buedwig4.feishu.cn/wiki/Y9o2wgZWXiEdECktg5pcVJPQnhf) 为准。

## 7\. 指标字典与协议成功

|指标|定义|
|---|---|
|`ttfb_ms`|HTTP 响应头到达时间减请求开始时间|
|`ttfe_ms`|首个合法协议事件减请求开始时间|
|`ttfc_ms`|首个用户可见内容减请求开始时间|
|`ttft_ms`|首个文本 token 或 delta 减请求开始时间|
|`first_thinking_event_ms`|首个 thinking 事件减请求开始时间|
|`first_tool_call_ms`|首个工具调用事件减请求开始时间|
|`total_ms`|合法终态或失败确定时间减请求开始时间|

控制事件属于 TTFE，不属于 TTFT；无文本输出的工具调用不得伪造 TTFT。旧 `firstTokenMs` 混合首个文本或工具内容，不能直接映射新指标；能从原始事件重算时重算，否则标记 `unavailable`。

|协议|成功条件|
|---|---|
|Chat 非流式|JSON 合法，内容或工具调用满足场景，finish reason 合法|
|Chat SSE|事件可解析、顺序与终态合法、终态后无增量|
|Responses|存在唯一合法 `response.completed`；failed 和 incomplete 不算成功|
|Claude 非流式|content、stop reason 和 usage 合法|
|Claude SSE|message 和 content block 顺序合法并到达成功终态|

HTTP 200、连接关闭、部分文本或产生费用均不能单独构成协议成功。

## 8\. Incident 聚合规则

Incident 聚合键由 `primary_fault_class + channel_id + model + user_group + protocol + route` 组成，滚动窗口是观测属性而非主键。同一键在冷却期内更新原 Incident，严重度升级立即通知。

配置变更前后的数据必须用 `config_change_ref` 分段。单个 Incident 可附多个 observation 和 Eval Run，但不能把不同渠道或协议故障强行合并。

## 9\. 联调方向与最小语义

### 9\.1 Monitor 触发 API\-evaluator

Monitor 只能创建受控 Eval Run，不传任意地址、密钥、认证头、原始提示词或用户正文。请求语义至少包含契约版本、Incident、Target、Suite、场景、时间窗、证据引用、预算策略和配置变更引用。

幂等键由 Incident、Target、Suite 和配置变更引用组成。同一幂等键和相同载荷返回原 `eval_run_id`；相同键但载荷不同返回冲突，不创建第二个任务。成功受理表示排队，不表示测试完成。

### 9\.2 API\-evaluator 发布结果

API\-evaluator 通过 transactional outbox 发布结果事件。最小语义包括契约版本、事件时间、Incident、Run、Target、主/伴随故障、证据等级、置信度、建议状态、样本统计、统一指标、证据引用和恢复门禁。

Monitor 以 `event_id` 幂等消费。重复事件不重复改状态或通知；撤回通过新事件表达，不删除历史。API\-evaluator 只发布证据和建议，不调用 NewAPI 写接口。

### 9\.3 错误、重试与乱序

|类别|语义|调用方动作|
|---|---|---|
|参数或枚举错误|契约不合法|不重试，进入失败队列并告警|
|身份或权限错误|服务授权异常|不盲重试，通知凭证责任人|
|目标不存在|配置或关联错误|不重试，人工核对|
|幂等冲突|相同键对应不同载荷|不重试，生成 SEV2 数据契约事件|
|负载过大|内嵌证据超限|改传 evidence ref，不重试原载荷|
|限流|对方容量保护|遵守 Retry\-After，退避并加入 jitter|
|暂时不可用|服务端短期故障|有界重试，耗尽后进入失败队列|

重试必须复用相同幂等键和载荷哈希。事件允许乱序；旧事件只补证据，不回退更新后的状态。失败队列须支持人工重放并保留原失败原因。

## 10\. 版本兼容

- `schema_version` 必填；

- 同一主版本只允许增加可选字段；

- 删除字段、修改语义或不兼容枚举须升主版本；

- 生产方与消费方至少在一个发布周期内兼容当前和前一主版本；

- 未识别的必需枚举必须拒绝并告警，不得静默映射为 `unknown`；

- Schema、接口定义和持久化枚举由 CI 做一致性校验。

## 11\. 渠道定向与命中证明

每个 Target 绑定唯一内部测试分组，测试时该分组只保留目标渠道并关闭跨组重试。执行前后须验证测试身份、分组成员、模型映射和路由策略，并由 NewAPI 日志反查实际 `channel_id`、模型、分组和 Attempt。

实际渠道与 Target 不一致或无法证明时，结果为 `Unavailable`，fault class 为 `telemetry_gap`，不得参与准入、隔离或恢复。恢复灰度可以在观察分组中列出少量批准渠道，但每个请求仍须记录实际命中。

## 12\. 状态冲突仲裁

|Monitor|API\-evaluator|仲裁|
|---|---|---|
|异常|异常且 `exact`|取更严重建议，进入人工审批|
|异常|正常|保持异常状态，继续真实流量观察|
|正常或低样本|异常且 `exact`|进入 `SUSPECT`；重复确定性失败可建议 `DEGRADED`|
|正常|正常|不自动变更，按既有状态和恢复门禁处理|
|任一关键数据源不可用|任意|不判 `HEALTHY`，显示数据盲区|

人工覆盖必须记录理由、批准人、有效期和恢复条件；到期重新按规则计算，不永久压制事件。

## 13\. 两段式恢复门禁

第一段由 API\-evaluator 完成：原故障场景连续 5 次通过，30 分钟内至少 20 次文本请求且成功率不低于 99%，流式请求全部合法终止，无同类连续故障，计费和路由命中一致。通过后只能建议 `RECOVERY_PROBATION`。

第二段由 Monitor 完成：低权重或低优先级灰度 30 至 60 分钟，至少 50 个真实文本请求，错误率和 TTFB、TTFE、TTFT 回归近期基线，且无关键错误和同类 Incident。通过并经人工审批后才可回到 `HEALTHY`。

低流量渠道 60 分钟不足 50 个请求时，不自动恢复。可延长至 24 小时，或由两名负责人批准使用“20 个真实请求、两个独立时间窗、API\-evaluator 深度套件”作为例外，并完整记录。

## 14\. 敏感数据边界

- 精确请求或用户查询使用受控请求体，不把敏感值放入地址、浏览器历史或接入日志；

- 错误语义在采集端先完成密钥、用户内容、查询参数和身份字段脱敏；

- 完整提示词、响应正文、认证信息、密钥和 thinking signature 不进入 Monitor、工单、通知或截图；

- 原始证据只进入受限证据库，短期保留并审计访问；

- 客户端遥测须取得租户授权，使用短期上传凭证、防重放和采样同意；未接入时保持 `unavailable`。

## 15\. 契约验收

- 三系统使用同一枚举来源或生成包；

- 契约测试覆盖必填项、枚举、版本兼容和敏感字段；

- 重复、乱序、超时、限流、暂时不可用、失败队列和撤回用例通过；

- 未支持的主版本被拒绝并告警；

- 敏感字段不会进入地址、普通日志、页面、导出和通知；

- 定向测试的实际渠道命中率为 100%，否则结果不可用；

- 状态冲突、配置漂移和两段恢复均有集成测试；

- 任一联调方不可用时，不影响 NewAPI 正常文本请求。
