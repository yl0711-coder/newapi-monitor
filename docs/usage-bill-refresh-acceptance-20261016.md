# Usage 账单刷新恢复：本机验收

## 范围

仅本机开发分支。补充独立的“恢复上次账单”入口，不修改金额公式、账单列、来源查询、数据库结构或线上配置。未提交、打 tag 或发布。

原行为：刷新会丢失页面内任务对象，服务端任务仍在，但用户无法从页面找回。

新行为：

- 本标签页 sessionStorage 仅保存一个已取得的任务 ID 和记录时间，不保存签名票据、筛选、金额、文件或权限。
- 刷新不自动查询、不自动下载。用户明确点击恢复后，只 GET 原任务，并重新校验服务端返回的 ID、状态、条数、文件校验信息及权限结果。
- 恢复不发创建 POST。暂时失败可继续检查原 ID；401/403/404 清除本标签页记录，不展示旧金额或下载。
- 独立入口与按当前筛选新导出分开；恢复后明确提示使用上次范围，不应用当前筛选。
- 浏览器记录最多保留约 10 分钟，服务端的真实过期时间和权限检查仍是最终依据。浏览器禁用存储时不阻断原导出。
- 不承诺跨浏览器、关闭标签页后、进程重启后恢复，也不解决创建响应丢失且尚未取得 ID 的情况。

## 验收结果

- 前端相关 52 项测试通过。新增恢复 queued/running/ready/failed/canceled、503/429 后重查、权限失效、非法或错配 ID、伪造 ready、过期/未来时间/损坏存储、禁用存储，以及全新 JS 上下文模拟刷新。
- 普通导出和旧协议回滚测试同步通过。最初测试桩缺少新增按钮更新函数导致 4 项失败，补齐测试依赖后重跑全部通过，未放宽断言。
- Usage/账单相关 Go 回归通过（monitor 83.259 秒）；金额和任务内部包全量 race 通过。
- 已保存的 dx01 1,000 条样本在本机复制回放为 50,000 条，普通 CSV 与账单均逐条核对顺序、金额及总额通过。分别约 2.21 秒/28,197,848 字节、2.62 秒/7,568,440 字节，为本机样本结果，不是线上性能承诺。
- 首次样本回放使用相对路径，因 Go 测试在包目录执行而失败；改为已有样本绝对路径后通过。未重新拉取生产数据。

### Chrome + Docker 实测

本机临时 MySQL/Go 测试容器，1 CPU / 1 GiB，MySQL 禁用 TCP，仅发布 localhost HTTP。来源为 2,100 条合成记录，未配置生产凭据；Docker bridge 不等同于完全断网。

1. 无历史任务时恢复按钮隐藏。
2. 创建任务完成，显示恢复入口。
3. 刷新后弹窗关闭，恢复入口保留。
4. 点击恢复，重新显示 2,100 条并提示“上次导出范围，不应用当前筛选”。
5. 点击下载，Chrome 显示 176 KB、完成。
6. 下载文件 SHA256 与前轮已逐行核验文件完全一致：`a8923205a701b5d14329448581607fc833b404acb0c33108b4621e6f0a8d2163`。
7. 刷新前后临时目录均仅一个相同路径的账单文件，无重复生成文件；GET-only 行为另有自动化断言。
