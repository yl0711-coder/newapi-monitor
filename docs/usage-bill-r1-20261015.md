## 本轮开发范围

只增加 `internal/usagebill` 纯计算包及测试。没有 HTTP 路由、页面按钮、数据库读写、任务调度、配置开关、真实价格目录、Excel 生成、依赖变更或线上操作；现有生产代码未导入该包。

已实现的数学规则：

1. 本站文本钱包消费：原始整数 quota / 500000，按本账单约定解释为人民币；不再乘 7 或分组倍率。缺 quota 报错，负数不当消费，真实 0 保留。
2. 官方原价：各类已标准化用量 / 明确计价单位 × 已核验官方美元单价，精确求和后乘固定系数 7。支持不同单位和分开的缓存写入类别；没有完整价格不能当零价。
3. 折数：实际收费 / 官方原价 × 10；原价为零无折扣，实际为零且原价为正则为 0 折；超过 10 折如实保留。
4. 汇总：所有已确认实际收费都计入实际合计；只有完整价格匹配子集进入对比的分子和分母，不能平均各行折数或拿全量实际收费比较部分原价。
5. 使用不可变有理数，显示舍入与内部计算分开，金额累计不受 int64 总和溢出或二进制浮点误差影响。汇总器是任务私有的单写者，不承诺并发写入。
6. 固定规则版本 `usage-text-cny-v1`，独立于现有 `CostUSD` 或经营核算的币种解释。

重要前提：`PriceComponent` 只接收已经标准化且已核验价格的输入，不负责证明模型、协议、历史价格、收费模式、文本分类或客户权限。不能把此数学包直接接到任意日志上就称为可信完整账单。汇总结果也不是来源完整性证明。

- 覆盖千/百万 Token 单位等价、分开的缓存写入价格、缺失/非法/负数/过长价格、最大 int64 quota、累计超 int64、显示舍入不丢小额、不可变快照、并发读取及计数器溢出拒绝。

`LogContract` 必须来自经核验的来源版本证据。不能把当前线上版本套给全部历史记录，不能按模型名、URL 或猜测的升级时间选口径；未知来源只保留可读证据，标记不完整。

### 适配规则

1. 默认输入含缓存时，普通输入 = 原始输入 − 缓存读取 − 缓存创建；明确 anthropic 语义时，原始输入已是普通输入，不再次减缓存。
2. 缓存写入总量独立保留；5m、1h 和未拆分余量互斥，绝不把总量与分项再次相加。冗余 `cache_write_tokens` 只作一致性核对。
3. 仅普通文本生成器的创建总量零值省略可以归零；Anthropic 生成器始终写创建总量，因此其总量缺失不能归零。必写的缓存读取缺失、显式 null、非法数值不能归零。仅有 TTL 分项无总量时停止完整认定。
4. `claude=true` 却缺少明确计量语义、OpenAI 口径出现有歧义的 TTL 转换、分项超过总量、缓存超过输入、显式输入总量冲突等情况，保留原始用量，停止可信四类用量/价格计算，不钳成零、不猜版本。
5. JSON 限长 128KiB，数字按精确整数读取并检查 int64 边界；限制指数和数字长度，拒绝重复顶层键、尾随文档、数值字符串、负数和小数 Token。未知敏感字段不进入结果。
6. `TokenUsage.Complete` 只表示该条已知文本生成器的计量拆分可核验，不表示它属于钱包文本范围，也不表示价格、来源范围或权限完整。分类闸门尚待下轮，不允许直接据此导出正式账单。
