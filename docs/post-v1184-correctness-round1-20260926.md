# v1.18.4 后第一轮准确性修复（本地，未发布）

## 边界

- 基于包含 v1.18.4 的本地开发分支；保留已有未提交工作。
- 本轮只改财务小时台账缓存指纹、模型统计覆盖判断、自有站点余额汇总规则。
- 不改 NewAPI、生产数据库、采集频率、权限、ECS、发布配置和业务流量。
- 不新增数据库表，不增加 Redis，不开发四维经营分析。

## 修改

### 财务缓存

原小时台账指纹依赖 COUNT/MAX/SUM，会遗漏同秒的覆盖状态变更、分类版本变更，以及总金额不变的小时间修订。

改为按小时主键有序读取小型覆盖台账，流式计算内容指纹。包含状态、分类版本、金额/请求/内部测试指标，保留原有更新时间依赖；同时沿用核算覆盖谓词，检测零流量小时与已有正流量分钟事实的矛盾。查询使用本地库、原有索引；旧 SQLite 的 NULL 列按未知/零保守处理。

整份报表及月缓存使用相同修订依据，原有旧快照展示和异步更新路径不变。此修复不代表其他来源的版本检测或整个冷计算性能优化已全部完成。

### 模型统计

不移动查询窗口、不删除实时尾段请求、不改变请求计数和去重口径。新增两条来源的覆盖状态、水位及应定稿边界：已路由用户分钟事实、无可用渠道拒绝事实。

- 两条来源均证明整个请求窗口，才允许 `facts_complete=true`。
- 应定稿部分已核验、仅有正常实时尾段未定稿，显示 `pending`。
- 历史缺口、分类版本不一致、用户分钟投影不一致、拒绝来源缺少覆盖证明，保持未确认。
- 独立采集的当天游标不能证明之前多日完整，明确显示“仅证明当前日”，不伪造历史覆盖。
- 没有新增跨日覆盖台账或后台回填任务；跨日证明不足的能力仍需单独解决。

### 上游余额

上游账户视图提供 `exclude_from_balance_summary`。归并主域名为 `modelapi.link` 的自有站点不参与当前余额汇总；原余额、账单、日志和明细不删除。不改变消费、毛利、充值规则，不排除其他停用/停止使用供应商的真实余额。

## 验证

新增回归覆盖：同秒状态变化、分类版本变化、内部测试指标变化、更新时间变化、总额不变的小时重新分配、零流量矛盾、旧库 NULL；24h/3d/7d 实时尾段、历史落后、拒绝来源缺口、两源完整、版本不符、投影缺口、当天水位不可证明历史；自有/外部/相似域名、零余额、未知余额、停用供应商及明细保留。

前端测试使用 Node VM 执行实际 JS；Go 测试使用本地隔离 SQLite。Docker 验收以当前代码编译的 Linux 测试二进制运行，网络禁用、只读根目录、1.25 CPU / 768MB，不使用生产凭据、不替换本机预览容器。
