# Usage 账单：Token 计量与金额核验解耦

## 本轮边界

仅本机开发与隔离验收；不查询或写入生产、不发布、不改扣费、不修改数据库结构。
本轮只补 Token 兼容，不改变 14 列、官方参考价、订阅阻断、5 万行及 128MiB 上限。
价格覆盖、后台分卷和下载治理仍是后续项，不能将本轮通过等同于整个账单功能可上线。

## 原因和修正

旧的默认阶梯适配要求 `checkPortalBilling(...).State == matched` 才能补零创建数并展示普通输入。
这使已记录的零 Token、金额舍入边界、费用不一致等价格问题影响了独立的计量展示。

重新只读核对本机 NewAPI rc.26 对象 `8f6961c675932f406260ff0c218bc2aa0603e9b2`：

- `service/text_quota.go`：Prompt/Completion/缓存计量来自 usage，收费另行计算；Anthropic 明确记录 usage_semantic。
- `service/log_info_generate.go`：文本缓存读取必写、创建零值可省略；阶梯信息叠加到模块各自日志，不能仅凭 tiered_expr 就认为是纯文本。

因此增加独立的默认文本计量契约检查：已识别阶梯格式、wallet、文本路径、无 Claude 歧义、无媒体/任务/工具附加项、原始输入存在、整数计量和包含关系有效。只在此范围内解释创建零值省略。
未知模式、缺失/null/非法数、媒体/工具记录继续保护。原价与折扣仍经过原有严格金额核验。
冗余 input_tokens_total/cache_write_tokens 只用于一致性检查，冲突时不推导普通输入，不重复相加。

没有读取模型名称来猜计量语义，没有用当前部署版本套用全部旧日志，也没有把金额不一致改成一致。

## 本机验证

- 固定 dx01 1,000 条保存样本：普通输入/缓存创建留空从 77 条降为 8 条；逐笔金额、合计、时间、模型、Request ID 和顺序不变。
- 修正的 69 条包括 60 条已记录零 Token 和 9 条金额舍入边界。
- 8 条只保留工具附加字段的存在标记；私有采样时用 null 保守占位，不能说线上字段实际就是 null，也不能据此恢复工具内容。后续需核验必要字段，不能删除标记提高覆盖率。
- 默认输入 0..12、全部合法 read/write 组合穷举守恒；不依赖实际扣费匹配或输出字段存在。
- 增加真实零与缺失的区分、输入存在标记、负数/小数/溢出、缓存超输入、冗余总量冲突、工具/媒体/任务与语义歧义反例。
- 既有 10 笔批准样本与 14 列 CSV 逐格比较通过。
- Usage `TestPortal*`、`internal/usagebill` 全包、31 项前端测试通过。未声称全仓回归或人工浏览器验收已完成。
- 最终候选在断网 1 核/512MB Docker 通过新增计量边界、慢下载恢复、5 万条回放。普通明细 28,197,848 字节 / 3.117 秒，账单 7,568,440 字节 / 3.567 秒；放大后的 400 条保护对应原始 8 条，逐笔金额与计量守恒通过。容器自动删除。

## 大数据前序证据与限额结论

本机临时索引 SQLite，1 核/512MB、只读根文件系统、断网 Docker：

- 10 万/50 万/100 万行来源：账单超限拒绝，普通明细确认后仅导出最新 5 万条；这是超限保护测试，不是完整百万行导出。
- 5 万行每行 2KiB 合成说明：普通 CSV 111,539,192 字节，可导出；4KiB 说明触发 128MiB 限制、无半成品 CSV，并能再次导出账单。
- 慢下载注入：正常日志页仍可读；其他导出被全局限制拒绝，断线后释放名额并可重试。说明下载仍占生成名额，需后续独立治理。
- dx01 样本放大 50 倍只是性能回放，不是 5 万条独立真实请求，也不是线上 RDS 导出时间。

当前不提高 5 万条/128MiB 上限。月份是账期选择，不是容量保护；完整大账期需要受控后台任务、分卷、总耗时与磁盘预算，不能静默截断或把总量限制伪装成完整账单。
