# 每日内部测试成本证据状态修复（本机）

## 确认的问题与范围调整

原计划继续核对每日账户总成本与内部扣减的同源关系。检查先发现明确错误：`buildFinanceDailyViews` 已取得每日成本证据，却调用 `applyFinanceInternalTestCost(..., 0, 0, false)`，导致混用与未核验计数丢失，完整内部成本也始终显示为仅已识别。

本轮优先修正这一信息失真，不扩大到跨来源净成本发布。未修改收入、赠送、成本金额、扣减公式、利润公式、采集器或数据库结构。不访问生产、不下载新数据、不补采、不提交、不打 tag、不上线；不操作 8100。

## 修改

- 每日结果使用实际 `MixedPairs`、`UnverifiedPairs`，不再固定为 0。
- 内部成本完整性同时要求当日内部账号范围和成本证据完整；只有满足要求的严格识别金额才设置完整内部成本指针。缺失来源或混用不能冒充完整。
- 每日新增 `internal_cost_complete`，区分证据待补、已核验有金额、已核验未发现内部成本；缺少记录不凭空生成 $0。
- 日表原“内部测试上游成本”列增加小字说明：混用待拆分、未核验、证据待补，以及原配对账本扣减待核对。数量单位是渠道小时配对项，不是请求次数。
- 提示明确区分独立识别的内部金额与账户账单；不能让用户误以为可以直接把相邻两列相减。
- 月组件缓存 schema 15、报表键 `daily-internal-evidence-v1`、finance.js v52，避免复用旧状态。

## 测试

新增红测试确实复现：严格/零成本的完整性指针丢失，混用/未核验计数错误为 0。修复后覆盖严格、混用、未核验、缺来源、缺账号范围、已核验前缀、明确零、无事件与缓存 JSON 往返；某日有缺口不污染次日。

初次夹具把全局 Complete 设为 false，但仍保留覆盖全部日期的 VerifiedScope，按现有规则这些日期仍有效。夹具改为真正缺少已核验范围，并另加“全局未完成但前缀完整”的正向测试；没有放宽业务判定。
