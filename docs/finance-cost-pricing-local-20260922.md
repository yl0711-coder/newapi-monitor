# 内部测试扣减的历史计价校验（仅本机）

## 本轮目标与边界

账户账单按查询时有效的历史充值版本计算，内部测试金额来自已发布的经济事实账。上一轮供应商范围与金额上界校验，无法证明两者计价依据一致。本轮仅增加这一层保护，不修改利润公式、渠道报表、采集器或任何数据库结构；不补抓线上数据、不部署、不提交或打 tag，也不操作 8100。

最初红测试：账单修正总额 $33，内部账本存在缺少计价依据的 $1 测试成本，旧代码仍发布净值 $32。红测试确实失败并记录旧错误值。后续将集成夹具进一步收紧为：版本 1 比例 1:1，版本 2 同一时刻生效且比例 2:1；账单修正总额 $36，而旧内部金额仍为 $1，必须拦截不一致扣减。

## 修改内容

- 内部测试事实的只读 SQL 投影携带已有 `finance_version`；严格内部事件及月/日子范围保留该字段。
- 对需要跨来源扣减的供应商，一次批量读取本地历史充值版本；不逐条查询，不请求上游，不用当前可变配置伪造历史证明。没有内部扣减或使用同一经济事实账回退时不新增查询。
- 校验发布版本确实存在、有效且在当时已生效；该小时有效充值比例与发布比例一致；小时内发生比例变更则不猜测分摊。
- 用有理数比较比例，按经济事实账既有整数微美元舍入规则重算测试成本，再检查事件行数、原成本和修正金额与分项一致。仅版本号变化、比例不变，允许继续扣减。
- 不匹配时保留已知原成本、已知内部成本，沿用上一轮状态与小字说明，不发布净客户成本，不让该数据问题使整张报表报错。真正的 SQLite 查询错误仍走原有报表错误路径。
- 月组件 schema 12、全报表键 `internal-cost-pricing-v1`；事件版本进入原有输入指纹，防止旧扣减结果被缓存复用。无前端文件变更。
