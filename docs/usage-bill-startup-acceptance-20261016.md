# Usage 后台账单启动与完整 HTTP 验收

## 本轮范围

- 新配置 `MONITOR_PORTAL_BILL_TASKS_ENABLED`，仅精确 `true` 启用，默认 false。
- 接入正常 `RegisterPortalRoutes` 启动路径；不需要另外启动脚本或独立容器。
- 补充配置示例，不修改任何实际生产环境文件。
- 不改计费公式、CSV 列、金额、5 万条上限、SQLite/MySQL 业务表或其他模块。
- 启动清理也拒绝被替换为软链接的暂存目录，防止在任务初始化检查之前跟随链接修改外部目录权限。

本文记录的是本轮代码状态；此前验收文档中“未接入正式注册”的表述是各轮当时的边界，不代表本轮仍未接入。

## 开关行为

| 状态 | 客户账单 | 其他 Usage 功能 |
|---|---|---|
| false / 未配置 | 不启动任务 worker、不挂载任务路由，保留原同步账单入口 | 保持原行为 |
| true，初始化正常 | 预检返回 `bill_task_contract=1`，使用后台一致性快照导出 | 普通 CSV、登录、日志列表不变 |
| true，初始化失败 | 账单预检与任务接口明确 503；不发票据、不静默回退 | 登录、日志、普通 CSV 可继续使用 |
| true，旧页面请求同步账单入口 | 409，提示刷新页面，不绕过已选择的快照模式 | 普通 CSV 不受影响 |

这是进程启动配置，不支持运行中改布尔值热切换。Monitor 未启动客户 Portal 时，不会仅因该开关为 true 启动任务服务。

成功启动还不等于所有来源适用：生成器要求已验证的 MySQL/InnoDB、只读来源权限及足够临时磁盘空间；来源暂不可用、数据校验失败仍整份拒绝，不能输出部分账单。

## 本机验收

### 配置与故障隔离

- 默认不创建 worker、不创建任务目录、任务 API 返回 404。
- 精确 true 才激活；空值、false、TRUE、1、拼错值不激活。
- 开启后正式注册并提供能力标识；关闭服务后不再提供能力标识。
- 对任务目录注入软链接造成初始化失败，确认账单 503，同时登录、页面、日志列表和普通 CSV 完整下载仍成功。
- 已签发的旧同步账单票据不能绕过后台模式；无账单标记的普通 CSV 票据不受影响。
- 暂存父目录为软链接时，拒绝跟随，链接外目录权限不被修改。

### 真实 MySQL + 真实 HTTP 合成链路

仅在本机 `mysql:8.4.9` 临时容器执行：断网、无映射端口、数据库目录 tmpfs，所有账户与库都是本轮合成测试创建。业务读连接只获日志表 SELECT。HTTP 使用本机 httptest 服务器，不连接线上。

走正常路由注册与完整预检，不手工拼造成功下载响应：

预检 → 创建任务 → 查询状态 → 一致性快照生成 → 私有文件 → HTTP 下载。

- 2,100 条：179,733 字节，测试约 0.11 秒。
- 50,000 条：4,339,134 字节，测试约 1.31 秒。
- 两组均逐条核对全部 Request ID、顺序、14 列和实际收费，核对文件 SHA256、Content-Length、文件字节数、总行数及 EOF。
- HTTP 下载完成后来源连接池 InUse=0。
- 模拟 HTTPS 反代保留公开 Host 的请求成功；伪造 X-Forwarded-Host 不能绕过 Origin 不匹配拒绝。
- 重跑并发 UPDATE/DELETE/INSERT 的快照一致性，以及条数错误、权限变化、取消、超时、NULL 金额、非 InnoDB 失败释放测试，均通过。

测试限制：这是本机合成数据，不代表线上 RDS 网络延迟、完整历史价格覆盖或浏览器扩展下载行为。50,000 条是现有上限内验证，没有开放 100 万条生产导出。

### 环境失败如实记录

第一次容器配置 /tmp=256MiB，不满足原有磁盘保留余量，正确返回 507/insufficient_storage；之后 768MiB 容器 OOM 退出，不能算该轮验收通过。

重新创建为 1 CPU / 1GiB 内存、/tmp 最大 1GiB，并将 Go 测试进程 GOMEMLIMIT 设为 256MiB，再次执行完整链路通过。没有降低程序磁盘安全阈值；该容器同时运行 MySQL 和 Go 测试，不能据此推断生产 Monitor 单独需要 1GiB。临时容器测试完移除，不留测试数据库。

原生 Usage + Close/Shutdown 回归通过（20.229 秒）；静态检查通过。
启动/任务/生命周期 race 连续 3 轮通过（50.053 秒）；46 项前端相关回归通过。

## 启用、停用与回滚（说明，未执行生产操作）

1. 发布前对齐最新已上线基线、完成最终验收，固定版本镜像，保留当前镜像与原配置。
2. 默认 false 可保持原入口；正式启用需明确配置 true，并只重建 Monitor。Compose 示例已转发该变量；实际部署必须检查容器内生效值，不能只编辑宿主 .env 就认为已生效。
3. 反代必须保留客户公开 Host。Origin 与请求 Host 精确匹配，不依赖用户可伪造的 X-Forwarded-Host。真实反代拓扑仍需发布前核验。
4. 停用：配置 false 后正常重启 Monitor。关闭期间先取消生成，再关闭数据库；已打开的文件下载按既有关闭策略处理。客户刷新页面后回到同步入口，旧任务 URL 不再存在。
5. 回滚旧镜像：恢复原固定版本与原配置。此功能未新增业务表或修改原始账单事实，不需为它执行数据库降级；但不能删除或替换整个 SQLite 库。
6. 任务状态不跨进程恢复，重启/回滚后用户需重新生成。私有暂存文件不是经营核算事实库；旧版本可能留下任务目录，新版会按已验收的身份和文件锁规则回收。不能直接递归删除整个数据卷。
