# 历史分组增量修复：生产形态执行内核第一步

2026-09-29。仅修改本机代码并使用本地临时 SQLite/已有真实快照验收。没有 SSH、RDS 或上游请求，没有线上写入、重启、提交、打 tag 或发布。

## 为什么做这一步

现有真实证据已能逐小时安全补齐，但执行入口只支持 `LocalSnapshotOnly`。反复修复离线副本不会自动恢复线上经营核算。本轮开始解决接收端的执行边界，不再新增取证批次或第二套修复系统。

本轮限定为可在正常 Monitor 配置形态下运行的**内部执行内核**；HTTP、启动循环、自动重试、生产部署均不在本轮范围。代码内当前仅测试调用新内核。

## 修改

1. 新增 `MONITOR_FINANCE_GIFT_HANDOFF_LIVE_EXECUTION_ENABLED`，默认 false。必须启用固定来源授权；与本地执行/本地快照模式互斥，要求独立 Monitor 主库、事实库、只读事实连接与正常会话配置。
2. 保留原本地入口及其生产 DSN 禁止条件。抽出共同执行逻辑；新内核允许正常服务配置中存在外部 DSN，但自身不使用它、不查询源数据库。
3. 执行必须携带已有固定授权 ID；复用来源摘要、接收库身份、授权过期/撤销、单实例互斥、跨进程文件锁、逐小时限额、冷却、原子金额/身份核验及提交记录。没有任意路径或全量执行入口。
4. 台账只在显式执行且授权/源证据核验后初始化；未加入普通启动迁移。沿用 `local_gift_handoff_commits` 表名避免破坏既有副本兼容，写入范围仅 Monitor 自己的事实 SQLite，不涉及 NewAPI 表。
5. 原真实副本测试提取公共验收过程，让本地与生产形态内核共用金额、非授权目标、输入摘要和幂等断言，避免复制整套测试。

## 发现并修复的锁等待问题

首次台账 `AutoMigrate` 直接执行建表，正常写者持锁时实际等待约 5.06 秒；即使外层提供短 context，也可能受连接 `busy_timeout=5000` 影响。这不满足修复任务应及时让出资源的要求。

调整为先在同一事务中读取 schema，再执行台账迁移。存在竞争写者时读事务升级返回 busy，整个初始化回滚，不自行重试；正常写者释放后可以显式重试。

没有修改共享连接的 busy_timeout，也没有提高截止时间或削弱测试。初始化与修复都不跨冷却时间持有写事务。该修复同时覆盖原本地入口。

## 验收结果

- 新内核默认关闭、混用模式、关闭授权、免登录、正在退出、错误接收配置、来源不符、过期/撤销均拒绝，事实不变且不创建台账。
- 合成数据验证取消后保留首笔提交、显式续跑、重新打开数据库后幂等。新内核开关即使开启，现有本地 HTTP 执行/进度入口仍返回 404，没有悄悄启用生产操作。
- 正常写者占锁时初始化退出，释放锁后显式续跑成功；冷却期间通过另一 SQLite 连接正常发布新小时，修复不覆盖该新增小时或金额。
- 真实 438 条证据计划：本地与生产形态分别只批准 2/10 个用户小时、86 条；未授权目标、金额、源库、源审计和原接收备份均不变。再次执行结果相同，没有重复写入。86 条是已有证据的临时副本验收，**不累计为新增回填量**。
- 扩大赠送/交接/离线工具回归：monitor 71.953 秒、CLI 0.528 秒、导出包 0.553 秒通过；定向竞态检测 87.232 秒通过。`go vet`、golangci-lint 与差异格式检查通过。
- 配置默认行为、财务报表和缓存的补充回归通过（3.736 秒）。
- Linux ARM64 / Alpine 3.23 Docker 验收通过，包括真实副本、本地兼容、拒绝、锁竞争、续跑、配置边界。容器断网、只读根目录、只读输入挂载、1 CPU/1GiB、限额 tmpfs；源任务先复制到临时目录再锁定，测试后自动清理。无外部来源访问能力。
- 真数据用例使用测试等待函数避免重复冷却耗时；不把约 2 秒测试时间当生产吞吐。既有 HTTP 实际冷却用例另已验收，本轮重点是执行内核。
- 一次编译缓存权限错误属于环境失败，获准访问本机缓存后重跑；锁竞争的 5 秒失败是实际功能问题，修复后重跑通过，不混淆两者。

测试在显式白名单同步的隔离代码副本中运行，不掺入已有渠道、稳定性、用户目录等无关修改；其原差异摘要保持不变。原 8150 预览容器未替换。
