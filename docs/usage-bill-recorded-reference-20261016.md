# Usage 账单：日志基础单价参考金额接入与本机验收

## 本轮边界

仅开发工作树，本轮没有线上查询、线上写入、提交、打 tag 或部署。使用已有本机私有样本；不修改 NewAPI 计费、数据库结构、用户实际收费和 CSV 的 14 列名称/顺序。

用户已确认不要求独立历史官方价格目录：按该条日志的历史基础单价、命中档位、原计费变量计算参考金额。不是采用今天的价格，也不是把实际收费除以分组倍率反推。此前独立价格目录探索不作为当前导出的运行依赖。

## 实现

- 从已有公式核验路径取得精确基础金额，普通倍率、按次文本和有限线性阶梯表达式复用原有解析与校验。
- 参考金额不乘分组倍率，美元基础金额按已约定固定比例 ×7 展示为元。实际收费仍为原始整数 quota ÷500000；折扣为实际收费÷参考金额×10。零参考金额不输出折扣。
- 不按模型名称或特定日期硬编码允许范围；历史价格随日志保存的事实，不随当前配置变化。
- 先按日志公式及倍率校验实际 quota，再采用基础小计。阶梯按源程序浮点舍入核验，拒绝不一致，不使用“一额度误差也算对”的容差。参考小计使用精确有理数，不反算已取整金额。
- Anthropic 未拆分缓存按用户确认的同变量口径：原缓存总量保留参与上下文档位判断，计价仅使用已记录 TTL 变量，不新增推测的 TTL 收费。分项超过总量、仅有分项无总量等仍拒绝参考金额。
- 普通使用日志详情保留原有核验门槛。新增精确小计为非导出字段，不改变其 JSON 字段、公式显示或 CSV 详情。
- 工具/多模态/未知表达式等未覆盖记录不套用文本公式；缺原始 Token、未知单价或无法核验实际收费时参考留空。实际扣费继续保留；缺失原始 quota 或显式订阅账单仍遵循原有整体拒绝规则。
- 按钮提示说明“使用日志基础价格，不是独立核验的官方历史账单”；不新增客户说明列。

## 测试与结果

1. 新增基准测试：同模型不同历史价格、分组倍率与个人倍率不重复、免费分组、最低额度、按次、缓存、短长上下文边界、全表达式变量、错档、真零、缺值、未知来源、工具、多模态、分项冲突、浮点半值边界及输入不可变。
2. 首轮旧测试仍把所有非特定样本模型/日期的参考值视为不允许，失败已确认来自被取代的样本限制；删除这两项旧限制断言，并以逐笔独立金额断言覆盖新口径。其余异常价格/金额/来源门槛保留。
3. `go test ./monitor -run 'TestPortal|TestUsageBill' -count=1 -timeout=180s` 通过（10.942 秒）；含普通使用日志、账单、权限及导出回归。需要外部环境的 opt-in 测试未因此视为已执行。
4. `go test -race ./internal/usagebill` 及 `go vet ./monitor ./internal/usagebill` 通过。
5. 前端 evidence、rollback、bill-tasks 共 52 项通过；`git diff --check` 通过。
6. 已保存 dx01 单小时 1,000 条记录：992 条获得参考金额；8 条因采样将工具计费字段替换成 null，无法通过本机样本核验参考金额。这不是对线上原字段缺失的结论。实际扣费、时间、请求 ID、模型和排序逐条保留。
7. 同一批本机样本放大 50 倍至 50,000 条：独立整数算法逐笔核对参考金额、折扣，逐笔及汇总核对实际收费。账单 8,153,040 字节，约 3.624 秒；普通日志 28,197,848 字节，约 2.310 秒。49,600 条参考可计算，400 条对应上述 8 条重复样本，不是新增失败。独立价格表只在测试 oracle 中使用，不是生产模型定价目录。
8. Linux/arm64 二进制在断网、只读根文件系统、1 CPU / 512MiB、GOMEMLIMIT=256MiB 的临时 Docker 中通过本轮计价回归和上述 50,000 行回放。源样本只读挂载，临时容器自动移除。
9. Docker 初次使用 256MiB tmpfs，触发已有“最大导出文件预算+256MiB 保留量”空间保护，返回 507，无部分文件。改为 1GiB tmpfs 上限后通过，没有降低程序阈值；内存仍限制 512MiB。

以上耗时均为本机样本，不是生产 RDS 月账期的性能承诺。当前参考金额并不代表已经覆盖所有日志类型。
