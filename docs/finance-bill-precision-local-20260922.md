# 上游原账单日/月精度统一：本机验收

## 本轮目标与范围

接续每日账户原账单修复，解决相同来源按日与整段分别取整产生微美元差异的问题。仅修改经营核算原始账户账单的金额精度，不修改收入、注册赠送、内部排除、充值修正、利润公式、渠道展示或余额预计可用时间。没有生产查询、生产写入、补采、上线、提交或打 tag。

统一规则：每条通过现有完整性校验的来源账单桶，先四舍五入转换为整数微美元，再做带溢出检查的加法。原始 SQLite 浮点事实不改写。不同查询窗口包含相同来源桶时，精度一致；来源粒度或覆盖集合不同不应宣称必然相等。该规则不代表上游账单原始精度无限保留，每桶最大取整误差为半个微美元。

不将月度差额分摊给任意一天，也不按请求数摊成本。原账单含测试消耗，仍不是实付成本或利润。

## 实现与兼容

- 共用原账单桶校验；新增可选的已接受桶观察函数，渠道原路径不使用该函数，原浮点汇总及校验行为不变。
- 经营核算单独收集整数金额；域名后续出现非法账单/重叠，已收集的金额仍丢弃，不将其当作可发布部分。
- 日表、月表和供应商原账单明细使用同一整数规则；自然日关闭区间回退也使用同一规则。修正成本仍维持既有算法与来源。
- 金额转换拒绝达到 int64 浮点上界的输入，避免极端边界转换成负数；累加同样检查溢出。
- 月组件缓存 schema 8，全报表键 `bucket-account-bills-v1`，不读取旧算法报表为新结果，不删除原始账单或旧缓存文件。
