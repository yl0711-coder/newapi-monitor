# 经济事实账回退成本每日明细（本机）

## 本轮范围

仅补齐月表采用“经济事实账”来源时的日成本明细；不修改用户收入、内部扣减、充值修正金额、配对利润或渠道管理口径。不改采集器、数据库结构，不查询生产、不部署、不提交或打 tag，不操作 8100。

确认的差异：月表汇总经济事实账中成本已知的记录；原日账本汇总主要纳入已验证配对小时。若直接把原日配对成本用于回退成本明细，会漏掉成本已知但收入未配对的记录。

## 实现与保护

- 在已有经济事实账读取/遍历中，额外建立按北京时间日、供应商的已知修正成本索引，无新增 SQL 查询。该索引和已有用于内部扣减的“已验证日成本”索引分离，不改变其语义。
- 日明细严格跟随父期间的来源选择：仅纳入父期间 `CorrectionSource=经济事实账` 的供应商。父期间选择充值版本时，历史账本即使存在也不重复计入。
- 成本已知但收入未配对的金额作为“已取得”展示，不变成已配对客户成本或利润。无已知成本记录的未知小时不制造零；明确已验证空小时可作为零证据。
- 每个供应商逐一核对日明细合计与父期间已知回退成本。缺日、金额不一致、供应商之间差额抵消均不能通过；保留原月表，日回退列不发布金额并提示“日/月来源待核对”。
- 完整值采用保守门槛：父期间所选回退来源均有完整成本，且当天有各来源依据，才给完整值。否则仅展示已取得部分。这不是全平台成本完整性认证。
- 追加 `ledger_correction` 字段及“账本回退成本（含内部）”列，与充值修正列分开，说明二者来源互斥。旧响应缺字段时显示未知，不影响其他列。日表列数 18；finance.js v50。
- 月组件缓存 schema 13、报表键 `daily-ledger-cost-v1`；新的日字段进入缓存，内部索引不序列化。
