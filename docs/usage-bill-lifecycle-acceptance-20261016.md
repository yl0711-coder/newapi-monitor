# Usage 账单任务生命周期：本机验收

## 本轮范围

新增 `portal_bill_lifecycle.go` 和测试，补充 Monitor 关闭顺序及任务服务的关闭入口保护；没有改金额、CSV 格式、数据库结构、生产配置或页面。

`initPortalBillTasks` 仍是显式调用入口，正式 `RegisterPortalRoutes` 尚未调用它或挂载任务路由。因此普通启动不会启用后台账单，当前线上及既有导出行为不变。

## 实现与边界

- 同一个 Monitor 并发初始化只创建一个任务服务。服务开始关闭后不能重新初始化，新 HTTP 请求返回 503，避免关闭过程中再创建任务。
- 数据卷内使用独立私有子目录 `.portal-export-tmp/bill-tasks-v1`，不跟随该目录或其父级暂存目录上的软链接，不修改未知目录权限。
- **内核原本已经有过期轮询**，没有重复实现另一套过期算法。已有任务过期由内核处理；正在下载的文件等最后一个文件引用关闭后清理。
- 服务层每分钟调用已有安全回收器，处理启动时仍存活、后来退出的旧进程会话。活跃会话有文件锁保护；未知格式、部分初始化目录不强删。扫描规模及版本校验沿用已验收的回收器。
- Monitor 关闭时先停止账单生成及维护循环，再进入原数据库关闭流程。最多等待 5 秒；若生成器未按时停止，保留连接等待进程退出，不在运行任务下面关闭数据库。
- 已打开的下载只依赖文件，不要求保留数据库。关闭服务时不删它；下载结束后清理目录。重复关闭安全。
- 没有改业务库 schema。回滚到不含后台任务的旧版本后，旧任务不能续传，可能留下私有暂存目录；新版再次启动时按安全规则回收，旧版不会把它当业务数据读取。单任务服务的文件预算仍为 2 × 128MiB，不是无限保留。

## 本机测试

1. 20 个并发初始化调用返回同一个服务，只有一套生成 worker。
2. Monitor.Close 取消生成，测试生成器确认其退出前来源数据库仍可访问；维护循环随服务关闭。
3. 故意不及时响应取消的合成 worker：有界停止返回失败，数据库保持可用；放行后能完成关闭。
4. 下载中关闭服务仍可读完完整文件；最后 Close 后会话目录消失。
5. 软链接目录拒绝，外部目录无变更。
6. 短测试时钟驱动同一维护函数：旧的已识别无锁会话被回收，活跃会话和未知目录保留。
7. 真实内核定时器在无 View/Open/Submit 请求时回收过期账单；持有下载引用时仅标记过期、不损坏文件。
8. 服务关闭后的 HTTP 创建请求被拒绝并返回 no-store。

验证结果：

- 任务内核 race 连续 3 轮通过，约 5.29 秒。
- 生命周期及任务 HTTP 测试最终 race 连续 3 轮通过，约 38.25 秒。
- 本机 Usage 与 Close/Shutdown 相关回归通过，约 19.78 秒。
- Linux ARM64 断网 Docker：生命周期及任务 HTTP 测试通过（1 CPU / 512MiB）；空闲过期测试通过（1 CPU / 256MiB）。两个容器均自动删除，没有连接线上。
- 本轮 Alpine 容器中的 MySQL 集成测试按设计跳过，没有冒充重新验证；上一轮已经在隔离 MySQL 8.4.9 完成该链路。
- 静态检查及差异格式检查通过。
