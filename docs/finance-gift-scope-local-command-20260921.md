# 赠送核算范围补齐：本机手动验收入口

## 本轮边界

只增加 `cmd/financegiftlocal` 离线命令及配套测试。不接入 Monitor 启动、HTTP 接口或后台定时任务；不读取 DSN、不建立 SSH 隧道、不查询生产数据库、不部署。

使用已经下载的闭合 SQLite 备份和已经取得的原始日志范围证据。输入必须是按原查询流量过滤规则导出的证据，不能把任意日志拼接成证据。此次仅用之前取得的一个用户小时、11 条记录。

## 操作过程

1. `plan` 新建 0700 任务目录，复制原始备份，证据文件和审计文件使用 0600 权限。
2. 仅在副本上应用已有的赠送范围字段迁移；校验小时状态、来源代际、日志 ID、时间、金额、记录数和既有哈希。
3. 输出固定计划与 SHA256。此阶段不补齐任何记录，不接受覆盖已有任务目录。
4. 人工核对计划后，`run` 必须提供该 SHA256；计划或证据改变则拒绝执行。
5. 执行只操作任务目录中的 `usage-facts.db`，每个用户小时提交后将结果追加到 `audit.jsonl` 并同步落盘。
6. 重试同一命令即可恢复，已完整的记录只校验、不重复发布。数据库中已经验证的事实是恢复依据，不能用审计行数推算补齐金额。

示例（路径需替换为自己的本机备份、证据和新目录）：

```sh
go build -o /private/tmp/financegiftlocal ./cmd/financegiftlocal
/private/tmp/financegiftlocal -action plan \
  -backup /private/tmp/closed-backup/usage-facts.db \
  -evidence /private/tmp/original-evidence.json \
  -job-dir /private/tmp/new-gift-scope-job

# 核对上一步输出后，填写输出的完整 SHA256：
/private/tmp/financegiftlocal -action run \
  -job-dir /private/tmp/new-gift-scope-job \
  -confirm-plan PLAN_SHA256
```

每个计划 1—10 个明确用户小时，每份证据 1—100 条原始记录。本轮上限与此前只读导出样本保持一致，不是全量回填入口。

## 安全与恢复行为

- 原始备份只读复制；拒绝带非空 WAL/journal 的备份，并检查复制期间大小、修改时间变化。仍需操作者提供真正闭合的备份，不能把检查理解成任意活库都可复制。
- 任务目录使用内核文件锁，同任务跨进程互斥；进程退出自动释放。`job.lock` 文件保留是正常现象，不代表锁仍被占用，不要靠删除该文件解锁。
- 每次进程启动取得锁后先等待 10 秒，批内两个目标间也至少等待 10 秒。重启采用保守等待，不引入新的持久化调度表。
- Ctrl+C/SIGTERM 在目标之间停止；已提交数据不回滚，不自动推进后续目标。
- 审计失败立即停止；如果发现截断/非法/无关的审计记录，则拒绝追加。保留现场人工核对，不自动截断日志或静默跳过。
- 拒绝把任务数据库替换为符号链接或硬链接。任务目录不应交给其他程序同时编辑，也不能挂载为运行中 Monitor 的数据目录。
- 不改变用量金额、请求数、退款金额、全量同步游标；只在逐条核对通过后补充缺失的分组归属。
- SHA256 用于发现输入变化，不是上游签名，不能证明任意手工编辑的文件来自上游。

### 实际发现并修复

离线证据原来用普通 `string`/`int64` 接收 `group`/`quota`，缺失字段或 JSON null 会默认为空字符串/0。缺失分组可能被误标为已知，缺失金额可能冒充确切的零金额。

先新增回归用例复现四个失败，再改为保留字段是否提供的信息：缺失或 null 拒绝导入，明确空字符串和明确 0 保持兼容。证据转换为查询源时也再次校验，避免绕开准备阶段校验。此修复仅作用于尚未上线的离线命令，不更改生产采集协议或经营计算公式。

测试代码按可复用混合账本夹具和表驱动场景组织，没有复制新的采集器或报表计算实现。

最终结果：

- 本地离线用例、混合用例全部通过；赠送补齐及缓存相关竞态回归通过（含既有真实样本）。
- 财务与渠道相关扩大回归、`internal/financecredit`、`go vet`、diff 格式检查通过。
- macOS 和 Linux amd64 离线命令构建通过；Linux 本轮仅交叉编译，未部署。
- 更新后的实际命令兼容上一轮任务：核对 11 条、更新 0 条、内容哈希不变；原始备份和原始证据 SHA256 均不变。

剩余边界：退款仍遵循现有经营/排除范围的赠送估算口径，不是按原始请求逐笔验证退款资金来源。真实多用户、多小时源数据尚未新增取样；全部历史补齐、线上调度、生产部署均未启动。下一步进行本地报表联动验收，核对部分/完整状态、明细及缓存刷新，不直接扩大生产回填。
