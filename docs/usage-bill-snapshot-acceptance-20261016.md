# Usage 账单来源快照：本机 MySQL 验收

## 本轮改动边界

新增 `portal_bill_snapshot.go`、`portal_bill_snapshot_test.go`，没有修改现有路由、页面、计费公式、生产配置或数据库结构，没有访问生产数据库。代码尚未接入客户接口，不改变当前导出上限。

这一步给上一轮的完整 14 列生成器提供真实数据库快照及独立统计，不再把 ID 上界当成完整的来源冻结。

## 实现

- 仅接受服务端已核验的成员及筛选，复用现有 `logFilterWhere`，强制消费类型；最多 31 天范围，最多 100 万行内核边界，不代表生产允许此容量。
- 复用导出泳道和来源共享并发预算，不额外开无限并发。
- MySQL `READ ONLY`、`REPEATABLE READ` 事务内，第一条统计查询建立读视图；独立获取行数、最大 ID、DECIMAL 原始 quota 总和、无效金额计数，随后分页使用同一事务。
- 不使用 `FOR UPDATE`、表锁、写入、全局或会话级配置变更。访问日志表后校验 InnoDB 引擎，借助事务内元数据锁防止校验与分页之间切换引擎；非事务引擎或校验失败不降级。
- 全流程（含排队、授权、读取和暂存生成）设置 15 秒预算，每条来源 SELECT 附带 8 秒执行提示；任意失败整份丢弃，不能发布前缀 CSV。
- 生成前后核对授权；独立统计与逐行 ID、排序、条数、quota 校验共同生效。完成后显式结束只读事务，下载不再占数据库连接。
- 数据语义是生成快照时点的已记录消费，不是承诺下载时仍与可变源库完全相同。快照之后新增、修改、删除的记录留待重新生成。

依据：[MySQL 一致性非锁定读取文档](https://dev.mysql.com/doc/refman/8.0/en/innodb-consistent-read.html)。一致性读取不等于零资源成本：事务期间仍占一个连接、读视图和元数据锁，可能短暂影响 DDL；因此必须限时、限并发，不能把它延伸到客户下载期。

## 本机验收结果

环境：已有 `mysql:8.4.9` 镜像，临时容器 `--network none`、不发布宿主端口、1 CPU / 768MiB、数据目录 tmpfs；仅通过容器内 Unix socket 创建临时合成库。生成器使用仅有目标表 SELECT 权限的独立测试用户。

1. 2,100 条日志分多页，第一页完成后，另一连接修改未读取记录的金额/Request ID、删除未读取记录并插入新记录。并发写入成功；生成文件仍含全部原始 ID 和原始收费，没有新旧混合。
2. 验证生成器使用的账号不能 UPDATE；统计和分页没有写源表。
3. 条数不一致、授权撤销、取消、短截止时间、NULL quota、非 InnoDB 均失败；逐项核对实际失败原因，不能用任意 SQL 报错冒充目标边界通过。
4. 成功与各失败分支后，来源池 `InUse=0`，并能继续 Ping，未把来源连接留给下载。
5. 100,000 条真实 MySQL 合成日志，全 14 列 CSV 为 8,689,135 字节，生成约 1.62 秒。逐条核对 Request ID、实际金额、总行数、末尾 EOF 通过。与上一轮不同的合成模型名导致字节数不同，不是字段裁剪。
6. 现有 `TestPortal*` 回归通过（约 9.67 秒），`go vet ./monitor ./internal/usagebill/...` 通过。

首轮测试合成表缺少排除平台测试日志所需的 `token_id`，导致 SQL 拒绝；补齐测试表并强化失败类型断言后重跑通过，没有为通过测试删掉生产过滤条件。上述结果不代表生产 RDS 网络延迟、真实历史复杂元数据或整月高并发容量已验证。
