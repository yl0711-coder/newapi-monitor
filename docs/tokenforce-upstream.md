# 海南海纳（TokenForce MaaS）上游接入

海南海纳不是 NewAPI 或 Sub2API。Monitor 必须选择独立的“海南海纳（TokenForce MaaS）”类型，不能用已有适配器猜测字段或金额单位。

## 配置项

在渠道管理中找到 `hainahn.com` 主域名，进入倍率/上游账户配置后填写：

- 站点地址：`https://maas.hainahn.com`
- 组织 ID：当前登录组织的 `orgId`。不是公开租户配置里的 `tenantId: 8`，也不是 API Key ID、API Key 名称或本地令牌名。
- Refresh Token：优先使用对方提供的只读服务账号或正式管理 API Token。若只能使用网页会话，先在上游网站完成人机验证，再把该会话的 Refresh Token 直接填入 Monitor；不要粘贴到聊天、日志或工单。
- 人民币结算换算：每 1 USD 对应多少 CNY。余额和调用日志的原始金额是人民币，Monitor 用该值归一到现有美元报表。
- 使用日志同步：余额验证成功、币种口径确认后再开启。

Monitor 不保存上游登录密码，也不自动绕过阿里云验证码。保存 Refresh Token 时会立刻调用 `/api/sys/login/refresh` 换取新会话，并只加密保存轮换后的凭据；页面不会回显令牌。

## 金额口径

接口原始余额和 `costInCny` 按 CNY 保留，同时以以下公式进入现有 USD 汇总：

```text
账面成本（USD） = costInCny ÷ CNY/每 USD
账面余额（USD） = currentBalance ÷ CNY/每 USD
```

“充值支付 / 充值到账”仍是另一层修正，用于折扣、赠送或非 1:1 到账，不能把汇率再填一次。例如实际支付 ¥900、到账 ¥1000，则填 900/1000；CNY/每 USD 单独按结算汇率填写。这样不会重复换算。

修改 CNY/每 USD 会改变历史金额语义，因此 Monitor 会保留旧数据的归档证据、清空当前发布水位，并按新口径重新拉取最多 7 天数据。不能在同一数据集中混用两个汇率。

## 同步与数据保护

- 余额：`GET /api/orgs/{orgId}/balance`，使用 `currentBalance`；充值余额、赠送余额、信用额度和欠款暂不混入“当前余额”。
- 用量：`GET /api/usages/detail`，按 `orgId`、起止时间、页码和每页数量读取明细。
- 认证：`POST /api/sys/login/refresh`，Access Token 即将过期或接口返回 401 时最多刷新一次，轮换后的 Refresh Token 会加密覆盖保存。
- 分页：逐页核对 `totalElements`、页大小和首页指纹。扫描过程中发生变化时整窗重试。
- 去重：按 `requestId` 检查单页、多页和拆分窗口间重复；发现重复不会发布该窗口。
- 完整性：任何日志缺少 requestId、requestTime、costInCny，时间越界、金额非法或计数溢出时整窗失败；旧的已发布账目保持不变。
- 高密度：单窗口超过安全页数时自动二分时间区间；仍无法完整读取则失败，不截断。
- 回补：在接口没有正式文档前最多回补 7 天，避免触碰网页已知查询边界和持续压迫上游。
- 计价证据账本：此平台的明细能证明实际扣费，但不能证明 NewAPI 式分组倍率；因此不会自动更新渠道倍率，也不会伪装成“倍率证据已验证”。
- 渠道归因：当前发布的是 `hainahn.com` 上游账户/主域名的小时汇总。接口明细没有已确认的本地 NewAPI 渠道 ID 映射，因此不能把账户总成本强行拆到某个本地渠道；只有在真实样本确认两端 `requestId` 稳定一致后，才可以增加请求级影子关联和渠道归因，关联失败的金额仍必须保留在“未归属成本”而不能丢弃。

## 上线前真实验收

该平台使用未公开的后台接口，模拟测试通过并不等于接口契约已得到供应商承诺。正式开启前至少核对：

1. 用专用账号读取一次余额，Monitor 的原始 CNY 与页面余额一致。
2. 选一个完整小时，导出或人工核对上游明细总条数、输入/输出 Token 和 `costInCny` 合计。
3. 确认接口的起止时间是半开区间 `[beginTime, endTime)`，边界请求不重复也不遗漏。
4. 确认 `costInCny` 是最终实际扣费而非目录价，退款或冲正记录的表达方式也要确认。
5. 抽取一批同时间段请求，确认海南海纳与本地 NewAPI 日志中的 `requestId` 是否相同；未确认前只验收账户总成本，不验收本地渠道成本归因。
6. 让供应商确认接口、字段、分页基准和 Refresh Token 轮换规则可以长期使用；最好提供只读服务账号。

在以上核对完成前，可以部署适配器代码，但不应给该账户开启正式成本/利润口径。
