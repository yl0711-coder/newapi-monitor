# Usage 后台账单：页面交互本机验收

## 范围与启用边界

本轮增加账单任务弹窗交互及导出预检的 `bill_task_contract=1` 能力标识。不改金额、Token 分类、CSV 14 列、5 万条上限、数据库结构或生产配置。

只有已显式初始化、已挂载路由且尚未关闭的任务服务才会提供该能力标识。正式 `RegisterPortalRoutes` 仍未初始化/挂载后台任务服务，因此普通启动仍走原有账单入口，不能把本轮完成等同于后台账单已全面启用。

有能力标识时走任务接口；未知版本拒绝。任务创建/状态失败后不会静默回退到同步导出或普通日志 CSV。无能力标识的兼容路径仍校验 bill-v1、消费记录上限和下载票据。

## 页面行为

- 显示提交、排队、生成、完整性核验、可下载、失败及取消状态。已整理完行数不等于文件已通过核验，进度最多显示 99%，ready 才显示下载入口。
- 任务 ID、状态、行数、总量、最终字节数和哈希格式校验；后续响应不得切换任务 ID 或总量。
- 创建进行中点取消，等待拿到任务 ID 后向服务端取消；只有收到确认才显示已取消。取消请求失败保留继续检查/再次取消能力。
- 查询中断保留当前任务，可继续检查而不重新生成。轮询次数有上限；并发点击不会重复创建。
- 创建响应丢失无法判断服务端是否已接收，明确显示“提交结果待确认”，不误称已取消、生成失败或下载成功。
- 权限变化、任务过期分别提示；未知后端异常不直接显示原始 SQL、凭证或错误详情。
- CSV 不通过 JS Blob 缓冲；生成完成后由用户点击下载。页面明确“已请求浏览器下载”不代表文件保存成功。
- 弹窗最大宽度受视口约束，状态文本有 aria-live。

## 浏览器验收范围

使用实际 portal.html 中的导出 JS、弹窗结构和 CSS，配合仅监听 127.0.0.1 的临时合成接口，无登录、无真实客户数据、无线上连接。这验证的是实际页面交互，不是完整正式服务端与浏览器的端到端验收。

- 已看到排队、生成完成、明确下载入口。
- 下载点击被当前 Chrome 的迅雷扩展接管；只确认发起下载及页面没有误报成功，**未确认扩展最终保存文件**，没有修改浏览器扩展配置。
- 已看到取消请求确认前保持待确认，确认后显示取消成功。
- 已看到查询中断后的“继续检查”，恢复后到达可下载状态。
- 已看到完整性失败文案，且不存在下载按钮。
- 已看到任务过期后停止查询并提示重新导出，无下载入口。
