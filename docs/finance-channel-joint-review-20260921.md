## 确认的问题和口径差异

| 项目 | 证据与影响 | 处理边界 |
| --- | --- | --- |
| 旧赠送记录缺分组依据 | 新版安全规则发现历史 group_known=false；即使用户/充值小时及顺序记录齐全，赠送分配仍不可发布。普通推进水位不会自动重扫这些旧小时。 | 独立定向修复任务，不清表、不重置主同步游标。按用户/小时核对旧事实，原子发布，限速、暂停、重试幂等。历史源不可得时明确不可补，不编造分组。 |
| 分期赠送可用性过粗 | 整段范围有缺口时，先前独立可核验月份也被隐藏。 | 各期间独立验证从起算点到期间末的证据前缀；后段缺口不阻断先前期间，前段缺口不能忽略。缓存异步更新，保留旧结果。 |
| 日成本与月成本来源不一致 | 日表依赖配对事实，月表可以显示账户账单；不能保证日成本求和等于月成本。 | 区分账户成本时间归属和渠道精确归属；不能按请求数均摊来凑平。先一供应商一日验收，再推广。 |
| 成本排除范围不同 | financeCostExclusions 纳入非业务分组；渠道 loadFinanceConfiguredAccountCostEvidence 只处理已配置内部账号，且账号行预先排除了非业务分组。自动测试政策也不同。 | 明确“账户总支出”“客户业务成本”“内部测试成本”三个对象，再统一可比口径；平台利润必须承担全部真实成本，不能删除测试支出。 |
| 回退数字仍叫业务成本 | presentedBusinessCost 在业务成本不可用时显示账户原值；小字说明暂含内部用量，但主标题仍为业务成本。顶部也可能混合严格扣除值和原值。 | 保留已知账单数字，但随数值来源调整标签；不可混合后冒充同口径业务成本。核算不允许使用该展示回退值。 |
| 过滤原因被统一显示为补齐中 | applyChannelInternalCostFilter 将 complete=false 一律标为 backfilling；混合小时、缺配对、来源证据不全本质不同。未知域名的未核验配对会全局阻断。 | 用结构化原因区分可自动补、需绑定/核验、无法严格分摊；有历史来源证明才按域名隔离，不凭当前渠道域名猜历史归属。 |
| 退款差异不够显眼 | 渠道查询 SUM(quota)，核算另取 refund_quota 得到净额。 | 保留扣款总额用于对账，明确桥接：渠道扣款 − 客户退款 = 核算净消费；净消费还要减赠送才是估算经营收入。 |
| 成本凭据仍缺 | 本机窗口 32 个相关已配置上游，31 个账单覆盖完整、16 个充值修正覆盖；AWS 产物未启用。 | 不把原账单直接当实付成本，也不把未启用 AWS 当 0。缺口按账单、修正、配对分别列出；不能承诺等普通回填就全部解决。 |

## 不应误判为缺陷的事项

- 当前预计可用天数读取原始上游账单日均消耗，不使用充值修正成本，也不排除测试消耗；这是余额实际流失口径。
- 禁用/恢复渠道没有清空倍率配置的代码路径；用户已重填，尚无具体渠道和变更前证据，暂不猜根因或改配置逻辑。
- 未配置的 208.98.41.154、360.cn、modelapi.link 不发起补采、不当同步故障。可报告已覆盖范围，但若产生消费而成本未知，不能声称全平台利润完整。
