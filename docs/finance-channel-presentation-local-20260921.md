# 第一轮：金额来源与状态表达修正（本机开发验收）

## 边界

在已有核算口径工作区基础上实施；没有修改生产、NewAPI、采集频率、金额计算公式或数据库表结构。没有启动历史补采，没有提交/推送/tag。原 8100 环境不变。

## 改动

1. 渠道页按当前可见账户为每个金额栏选择统一展示口径：全部可严格扣除配置内部账号时用扣除后值，否则统一用原账单（修正栏仍采用历史充值比例修正）。卡片与汇总共用规则，不混加两种口径。标题、小字随口径变化；只承诺扣除配置的内部账号，不声称全部测试均已剔除。
2. 旧 API 无明确核验状态时保持原值和“待确认”，不推断业务成本已核验；缺失/非法/负值不会成为零，真实零正常显示。无有效充值比例时不再显示虚构的 0×。
3. 保留自然日独立账单范围、区间完整性检查和分组/渠道筛选下的账户汇总限制，不拆分自然日、不改变余额剩余时间公式。
4. 渠道报表新增 `internal_scope_complete`；金额对象新增 `internal_filter_reasons`。保留原状态字段和金额可用性判定，新增字段只解释缺来源、混合用量、未核验配对、历史归属未知、金额不一致。
5. 数据同步状态原先未读取内部成本核验，现在复用渠道报表同一只读投影，包含自然日窗口核验。全局补数未结束不再被当成历史查询范围未完成。未配置上游单独提示，不列同步故障、不按零成本核算。
6. 经营核算复用已有利润计算明细，增加原生 details 展开的扣款/退款；只读后端金额，不在 JS 重算收入。依据不完整时显示已知部分，不冒充完整收入。
7. 更新静态资源版本。渠道两个接口原有 no-store 保留；财务金额与响应结构未变，不增加无必要的历史缓存失效。
