# 内部测试成本扣减范围保护（本机）

## 本轮范围与确认的问题

原计划继续检查经济事实账回退日归属和内部成本匹配，检查中优先确认了扣减风险：月表直接从已取得修正成本总额扣除全部严格测试成本，没有逐供应商检查扣减项是否属于已取得成本。

红绿夹具复现：账户账单/修正成本已取得 $33，另一个缺少成本来源的供应商有 $4 已识别测试成本。旧代码直接发布 $29；修复后保留 $33 原成本和 $4 测试成本，不发布扣减后的客户成本，标记待匹配。夹具真实调用 `buildFinancePeriod`，不是仅验证独立算术函数。

第二条已处理风险：日经济事实成本缺失但测试成本存在时，旧减法可能返回“缺少可相减金额”，导致整张报表失败。现保留已识别金额和明确缺口，不把缺失原成本当作零，也不让该扣减阻断其余报表字段。

本轮不扩展全平台利润或回填，不增加任何来源查询；只本机代码、合成夹具及已有真实 SQLite 副本验收。没有生产读取/写入、部署、提交、tag，8100 未操作。

## 实现

- 独立纯函数检查供应商映射、来源金额是否存在、来源范围是否可用于扣减、单供应商及总额上界、内部分项与总额/行数守恒，拒绝负数、超额和不一致证据。
- 充值修正来源若缺少该供应商整段完整成本证明，不用其部分账单承接另一套账本里的测试成本。
- 日账本复用已有已验证小时/行，在内存建立按日、供应商的修正成本范围；不按日重查数据库、不按请求数分摊，不改变渠道公共报表。
- 校验不通过时：原始已知修正成本和已知测试成本保留；扣减后的已知/完整客户成本清空；原总成本不再宣称完整，以免进一步发布完整利润。
- `internal_cost_deduction_status` 描述未匹配原因。跨月汇总保留该缺口，不将其他月份的净成本当成全区间净成本；原已知总成本仍累加展示。
- 前端用小字解释“原成本保留，扣减后金额暂不发布”，月表提供同样的悬浮说明。不改渠道余额或预计可用天数。
- 月组件 schema 11，全报表键 `internal-cost-envelope-v1`，finance.js v49，避免复用旧扣减结果。

## 未完成的边界

本轮是扣减必要条件校验，不是完整的逐笔成本来源证明。供应商范围和金额上界匹配，并不能单独证明账户充值版本与配对账本的历史计价版本逐笔完全一致；这一层仍需后续专项核对。经济事实账回退成本对外逐日归属也没有在本轮扩展，更不能宣称整个平台利润已经完整准确。
