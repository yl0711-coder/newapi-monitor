# 经营核算：完整期间被后段分组缺口隐藏（本机修复）

## 问题与边界

历史赠送分组证据补齐工具已通过多批真实证据验收，但数据修复进度不等于报表代码问题已全部解决。此前 `applyFinanceGiftBreakdowns` 要求整个查询窗口赠送证明完整，导致独立查询可核验的早期月份/日期，在扩大查询范围后也被隐藏。

本轮先以合成夹具复现失败，再修改发布范围。仅修改 Monitor 内存中的赠送核算投影、完整报表缓存键及测试；不修改金额公式、事实库表结构、原始金额、同步水位、采集频率或 NewAPI。没有读取线上、提交、打 tag 或部署生产。

## 修复规则

1. 用户小时、充值小时、来源、边界金额及逐条哈希全部通过已有检查之后，才允许从同一次读取中保留分组依据完整的连续前缀。其他证明缺失或内容损坏仍拒绝发布，不以此补丁绕过。
2. 截止点为最早未知非零金额事件所在小时的开始；同一小时其他用户即使已知，也不能发布这个不完整小时。
3. 不忽略起算点至查询开始之间的赠送钱包依赖；缺口在期初或更早时，不发布后面的期间。
4. 只有结束时间不超过该截止点的完整月/日行可以发布赠送扣减、经营收入；跨缺口的期间与整个查询总收入继续为空。内部账号与非业务分组、退款口径沿用原算法。
5. 使用已经读取并核验的内存账本，不按月份/日期追加数据库查询。不修改已完整窗口以及当前采样尾部的既有处理。
6. 完整报表逻辑键升级为 `gift-prefix-v1`，避免沿用旧投影；月度基础事实缓存键不变。旧快照不删除，缺口补齐后仍走既有指纹失效、异步替换流程。
