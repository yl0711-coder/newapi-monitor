# Usage 导出：生成截止、下载完整性与失败恢复

## 修改边界

仅本机账单工作树；未提交、未打 tag、未部署，未查询或修改线上数据库。复用已保存客户样本，只写临时测试数据库。
本轮不修改 14 列账单格式、实际扣费、Token 规范化、原价参考覆盖范围；不解除 5 万行和 128MiB 上限，不改业务表。

## 修复内容

原服务已有 HTTP 层两分钟 WriteTimeout，不能说原先完全没有超时保护。缺口是整份生成缺少应用层截止，以及下载最后一次缓冲刷新失败无法可靠反馈给导出成功计数。

- 整份生成预算 60 秒，覆盖权限读取、旧版参数查询、计数、每页读取和逐行处理；不随分页重新计时。
- 生成与发送共用两分钟总预算，发送阶段只取得剩余时间，不另加两分钟。
- 请求仍连接但生成预算耗尽：在 CSV 响应开始前返回 504 和明确错误码；已断开的请求不再写错误响应。
- 保持完整临时文件生成及末端权限复核后才发送；失败清理临时文件、释放跨进程锁和本进程名额、不记成功冷却。
- 增加 Content-Length，使客户端能识别未完成的响应；发送后不向 CSV 尾部拼入 JSON。增加 no-store 和 nosniff。
- 下载使用底层 net/http 写入截止，检查最终 FlushError；成功清除截止以保持连接复用，失败不重新放开连接写入。
- 全局导出名额仍保留到下载结束。没有为提速放开并发及磁盘预算；慢下载与生成队列彻底解耦留到后续独立任务设计。

这些是应用层协作式截止和网络写入截止，不是操作系统故障下强行中断磁盘 I/O 的保证。内存测试 writer 可不支持连接截止；已额外通过真实本机 TCP + Gin 验证实际网络路径。

## 验收

- Usage 专项回归、31 项前端协议及日志渲染测试通过；全部 Usage 专项及金额内核竞态检测通过。
- 普通导出、账单导出都测试了部分文件写入后的生成超时：无部分 CSV 响应、无残留文件、可立即重试。
- 测试最终缓冲刷新失败，不记成功限额；真实 TCP 客户端不读取时，服务端写入超时退出。
- 测试截断响应不能被 HTTP 客户端当作完整下载；成功后同一连接可跨截止时间继续复用。
- 单独测试生成耗时计入总预算，未重新开启完整两分钟。
- 已确认的 kjl 10 笔账单逐格一致；dx01 已保存 1,000 笔样本条数、顺序、Request ID 和金额一致。未知 Token 8 笔、参考原价 1,000 笔仍为空，未用虚构价格补齐。
- 断网、只读根文件系统、1 CPU / 512MiB Docker：合成数据 1千/1万/5万行以及 dx01 本机放大 50 倍（5 万行）通过。两次验收中，5 万行合成账单约 2.59—2.69 秒；dx01 放大账单约 3.33—3.72 秒、7,568,440 字节。最终候选也通过总预算测试。均核对条数与金额。不是生产 RDS 性能或 P95 指标；临时容器自动移除。
