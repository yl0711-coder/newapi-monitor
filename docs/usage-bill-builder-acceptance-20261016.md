# Usage 后台账单生成器：本机分页与金额核验

## 范围

本轮只新增 `monitor/portal_bill_builder.go` 和独立测试；未修改路由、页面、当前 5 万条导出上限、原价匹配、Token 和扣费口径。没有线上查询、写入、提交或部署。

生成器复用现有 `portalBillHeader`、`portalBillRecord`，与后台任务的私有暂存文件联测。SQL 验收使用临时本机数据库，通过实际 `queryGroupLogsForExportCursor` 查询，不是内存数组冒充数据库性能。

## 校验规则

- 只接受消费类型，冻结 ID 上界；分页最多 1000 条，输出最多 100 万条（仅内核边界，非生产开放上限）。
- 逐条验证时间/ID 倒序、ID 上界、ID 唯一性，包括同一 ID 改时间后再次出现的情况。
- 短页继续查询，不以“少于一页”直接认定全部读完；达到预计条数仍额外查询，发现多余记录整份失败。
- 独立预计条数、原始 quota 合计必须与输出一致。合计用任意精度整数，不使用浮点，逐条金额继续使用现有 quota/500000 口径。
- 查询、写入、进度回调、前后来源/授权核验失败均返回错误。生成器仅能写私有暂存文件，后台任务验证成功前不得发布；禁止直接绑定 HTTP 响应。
- 未知原价继续留空，不推导历史价格、不改变实际收费；已有订阅阻断等规则不变。

## 已完成的本机验收

- 客户已确认的样本逐列与既有生成函数一致，保持完整 14 列、Request ID 位置及金额格式。
- 漏单、多单、重复、修改时间后重复、分页乱序、越上界、非消费、金额不符、原始金额缺失、订阅、分页异常、前后校验失败、进度中断、取消均拒绝。
- 空账单和超过 int64 的累计 quota 核对通过，CSV 逐行金额相加与整数来源合计一致。
- 后台任务联测：成功文件能下载；行数相同但总金额不符时任务失败、文件不能下载。
- 本机合成数据库 100,000 行，CSV 9,489,135 字节，生成约 1.94 秒；逐行检查 ID 顺序、14 列内容和金额总和通过。仅此本机合成数据结果，不是生产 RDS、真实整月客户数据或并发容量承诺。
- 现有 `TestPortal*` 回归通过，约 9.65 秒。
- 断网、只读根目录、1 CPU / 512MiB 内存、512MiB 临时磁盘的 Linux ARM64 Docker 全部新增生成器测试通过；10 万条生成约 2.40 秒，完整逐行与金额对账通过，容器自动删除。
- 首次 Docker 临时磁盘只配置 256MiB，被已有“单文件预算 + 256MiB 余量”保护拒绝；未降低代码阈值，修正测试容量后重跑。失败测试进一步明确要求生成失败类型，避免把磁盘不足误判为金额校验成功。
- `go vet ./monitor ./internal/usagebill/...` 和差异格式检查通过。

## 尚未闭环，禁止直接接生产入口

1. 生产来源冻结：上界只能排除新增自增 ID，不能防止已有记录修改/删除；条数和金额相等也不能证明每个文本字段不变。当前生成器要求调用方提供不可变来源及前后身份核验。临时数据库测试中来源不变、核验回调为空实现，不代表已解决生产快照问题。
2. 预计条数、精确 quota 合计必须由与筛选/成员一致的独立来源统计取得，不能由生成循环自行填回。接入需要为生产数据库明确精确聚合、超时、连接持有和来源变化策略。
3. 本轮接入后台任务仅发生在测试中。生产的共享锁、授权会话、下载时限、任务路由和页面尚未接入。
4. 当前原价缺失规则未扩大。完整账期真实样本、大数据慢磁盘及跨进程资源预算仍需继续验证。

下一步先完成来源冻结与独立统计方案，验证数据变化时失败关闭，再接任务接口；不能仅凭本轮 10 万条合成数据通过就宣称可上线。
